第 I3 章：手顺1 —— 第一个 iFlow（Hello Echo）

集成包 → iFlow：HTTPS Sender → Content Modifier → HTTP Receiver → 部署 → 用 curl / Postman 验证

这一章走通第一个端到端 iFlow：外部调用者向你的 iFlow 发一个 HTTP 请求 → iFlow 用 Content Modifier 把消息改写成一段固定 JSON 并加一个请求头 → 通过 HTTP Receiver 转发给一个公网回显服务（postman-echo.com，它会把收到的内容原样返回）。你对比「发出去的」和「收到的」，就能亲眼看到 iFlow 在中间动了什么手脚——这就是集成中间件的基本功。前置：I2 环境就绪。

Integration Package HTTPS Sender Content Modifier HTTP Receiver Deploy MPL

I3.1 本次场景与「回显服务」说明

真实集成里，Receiver 指向的是某个业务系统（S/4HANA、你的 CAP 服务、第三方 API）。教学里我们不想依赖任何业务系统，于是用 回显服务代替：https://postman-echo.com/post 会把收到的 POST 请求内容（body、headers）包成 JSON 返回给你。它唯一的价值是「照镜子」——iFlow 送出什么，你从响应里就能看到什么。把下面的场景跑通后，把 Receiver 地址换成任何真实系统地址，iFlow 依然成立：

  • 调用者：你的终端（curl）或 Postman，POST {"ping":"pong"} 到 iFlow 端点。
  • iFlow：Content Modifier 把 body 换成固定 JSON {"msg":"Hello from CPI","course":"Integration Suite"}，并加请求头 X-Course。
  • 回显：响应 JSON 里 data 字段 == iFlow 改写后的 body，headers 里能看到 X-Course。

I3.2 步骤1：建集成包与 iFlow 骨架

  1. Design → 新建集成包

    进入 Design → Integration Packages，点 Create。名称填「iFlow 训练包」，技术名称（ID）填 iflow_course（ID 是包的命名空间，之后所有 artifact 挂在它下面）。

  2. 打开包 → 添加 iFlow

    点开包 → Artifacts 标签页 → Add → Integration Flow，名称 hello-echo，保存后在列表点它进入编辑画布。

I3.3 步骤2：画 iFlow（Sender → Content Modifier → Receiver）

  1. 配置 Sender（入口适配器）

    画布起点处有 Sender 占位。点开配置：General 名称 Sender；Adapter 类型 HTTPS；Connection → Address 填 /hello。Security 页保持默认（教学租户通常允许匿名调用，见I3.7）。

  2. 加 Content Modifier 处理步骤

    从右侧步骤面板把 Content Modifier 拖到 Sender 与结束点之间的流程列上（新版本 UI 也可在流程箭头处点 ＋ 添加）。选中它，底部出现配置区，做两件事：

    • Message Body 页：Body Type 选 Text，Body 填：{"msg":"Hello from CPI","course":"Integration Suite"} —— 把收到的任意内容替换成这段固定 JSON。
    • Message Header 页：添加一行——Name X-Course、Type Constant、Value integration-suite-training —— 给消息加一个自定义请求头。

  3. 配置 Receiver（出口适配器）

    画布终点处有 Receiver 占位。点开配置：General 名称 Receiver；Adapter 类型 HTTP；Connection → Address 填 https://postman-echo.com/post，Authentication 选 None。方法默认 POST（有 body 时发送方是 POST）。

  4. 保存

    点画布右上角 Save（或 ⌘/Ctrl+S）。保存的只是草稿版本，还没生效。

I3.4 步骤3：部署

  1. 点「部署」

    画布右上角 Deploy → 确认对话框（可写版本注释 first deploy）→ 部署。状态依次是 Deploying → Starting → Started，通常几十秒。

  2. 拿端点 URL

    切到 Monitor → Manage Integration Content，找到 hello-echo（状态 Started）。点它打开详情，复制 Endpoint URL——形如 https://<你的租户域名>/cxf/hello。规则：租户域名 + /cxf + 你在 Sender 里填的 Address。个别 UI 版本端点藏在行内「⋯」菜单里，找不到就按这个规则手拼（租户域名在浏览器地址栏）。

I3.5 步骤4：用 curl / Postman 调用并验证

把 <ENDPOINT> 换成上面复制的端点，在终端执行（发送什么内容都行，反正会被 Content Modifier 换掉）：

curl -s -X POST "<ENDPOINT>" \
  -H 'Content-Type: application/json' \
  -d '{"ping":"pong"}' | python3 -m json.tool

预期响应（来自回显服务）里能看到两处「iFlow 的手脚」：

  • data = {"msg":"Hello from CPI","course":"Integration Suite"} —— 你发的 {"ping":"pong"} 被 Content Modifier 换掉了；
  • headers.x-course = integration-suite-training —— 自定义请求头也成功加上了。

也就是说：接收方（这里是回显服务）收到的消息，已经不是调用者发出的消息——中间件对消息做了改写。真实验证脚本见 I6 测试数据 与 素材包。

I3.6 步骤5：看 MPL 运行日志

每次调用都会产生一条 Message Processing Log。进 Monitor → Message Processing Log，最新一条就是你刚才的调用，状态 Completed。点开它可以看到整条消息走过的每个组件：

I3.7 常见问题与注意

现象原因 / 处理
调用返回 401Sender 的 HTTPS 安全默认在部分租户要求客户端证书。教学环境可直接到 Sender → Security 页把 Authentication 设为 None（仅限教学；生产必须配证书/OAuth 等，属进阶话题）。
MPL 显示 Receiver 连接失败postman-echo.com 是公网第三方，偶发不可达；稍后重试或换个回显服务（https://httpbin.org/post）即可。它只是「镜子」，与 iFlow 本身无关。
改了画布但行为没变修改只是新草稿版本，必须重新 Deploy 才生效；Monitor 里能看到的版本号在递增（1.0.0 → 1.0.1…）。
找不到端点Monitor → Manage Integration Content → 点开 iFlow 详情；或按 https://<租户域名>/cxf/<Address> 手拼。
Content Modifier 的 XPath 用不了Body 类型选 Text 是「整段替换」；想从入站消息里抽字段需要 XPath/脚本，见 I4 手顺2。
✅ 本章验收标准 你能：① 说出 Sender / 步骤 / Receiver 在消息流里的角色；② 部署后从 Monitor 复制端点并成功调用；③ 在回显响应里同时看到改写后的 body 与新增的 header；④ 在 MPL 里找到这次调用的 Completed 记录。
