第 I4 章：手顺2 —— 消息转换

Content Modifier 深挖 · Groovy Script 步骤 · Message Mapping——把消息从「甲方格式」变成「乙方格式」

集成的大部分工作量是格式转换：甲方发的字段名、类型、结构与乙方要的对不上（A 系统叫 item，B 系统叫 product；A 给 JSON，B 只收 XML；金额单位还不一样）。本章把 Cloud Integration 的三件转换工具都过一遍，并用手顺做一个「订单金额换算」的真实转换：入站 {"qty":2,"price":11.11}，出站带上算好的 amount。继续用 素材包 里的样例载荷与脚本，无需自造数据。

Content Modifier Groovy Script Message Mapping body / header / property XPath

I4.1 再认识消息三件套

转换发生在「消息」上。每条穿过 iFlow 的消息都由三部分组成，先分清它们，后面所有步骤（含 I5 路由）才说得通：

Body（消息体） Header（请求头） Exchange Property（交换属性）
是什么消息正文：JSON / XML / 文本 / 文件内容随协议传输的元数据（HTTP 头、SOAP 头）只在 iFlow 内部传递的临时变量
谁看得见发送方与接收方接收方系统可见（作为 HTTP 头）只有流内后续步骤可见，不出租户
读取写法脚本里 getBody()脚本里 getHeaders()；配置里 ${header.xxx}脚本里 getProperties()；配置里 ${property.xxx}
典型用途业务数据本身鉴权信息、跟踪号、自定义标记暂存抽取结果供后续路由/组装（I5 主角）

I4.2 手段一：Content Modifier（轻量改写）

I3 只用了它的「替换 body + 加一个 header」。它的完整能力是三个编辑区：消息头（Header）、交换属性（Exchange Property）、消息体（Body），每个区的值来源都可以是常量（Constant）、XPath（从入站 XML 抽节点）或表达式（引用其它字段）：

Content Modifier 配置面板（三区）
消息头交换属性消息体
X-TraceId
Constant（常量）
req-2025-001
三个区可同时使用：Header 加请求头 · Exchange Property 存中间值（${property.xxx} 供下游读）· Body 换正文。
Type 换成 XPath 时可从入站 XML 抽节点（例：/order/type）；Type 换成 Expression 可引用 ${header.xxx} / ${property.xxx}。
图 I4-1 Content Modifier 三区：Header / Exchange Property / Body；「加静态头、抽个字段、改个正文」这类小活它最合适
💡 该用哪种「值来源」 Constant 写死值（版本号、渠道标记）；XPath 从入站 XML 消息取节点（带命名空间的 XML 需在面板里声明 ns 前缀，见 I5 注意）；Expression 引用本流内已有的 header / property。JSON 消息没有原生 XPath 支持——要解析 JSON 就用 I4.3 的 Groovy。

I4.3 手段二：Groovy Script（编程式转换）

Content Modifier 只能做「声明式」改动；需要解析 JSON、循环、计算、拼接时用 Script 步骤（Groovy 语言，Java 生态，内置 groovy.json 等库）。每个脚本实现一个固定签名：

import com.sap.gateway.ip.core.customdev.util.Message
import groovy.json.JsonSlurper
import groovy.json.JsonOutput
import java.math.RoundingMode

def Message processData(Message message) {
    // ① 读入站消息体（按 String 读，再解析成 JSON）
    def body = message.getBody(java.lang.String) as String
    def order = new JsonSlurper().parseText(body)

    // ② 业务计算：金额 = 单价 × 数量（BigDecimal 避免浮点误差）
    def amount = (order.price as BigDecimal)
        .multiply(new BigDecimal(order.qty as Integer))
        .setScale(2, RoundingMode.HALF_UP)

    // ③ 组装出站 body（JSON）
    def out = [
        book: order.book as Integer,
        title: order.title as String,
        qty: order.qty as Integer,
        amount: amount,
        status: 'OK'
    ]
    message.setBody(JsonOutput.toJson(out))

    // ④ 顺手存一个 exchange property / header，供后续步骤或接收方使用
    message.setProperty('computedAmount', amount.toString())
    message.setHeader('X-Amount', amount.toString())
    return message
}
  • API 就记五个方法：getBody / setBody、getHeaders / setHeader、getProperties / setProperty——与三件套一一对应。
  • 返回：必须 return message，否则消息不往下走。
  • 读 body：message.getBody(java.lang.String) as String 是最常用写法；直接 getBody() 返回的类型不定，优先显式指定。

I4.4 手段三：Message Mapping（图形化字段映射）

当转换是「结构化的字段级搬运」（XML → XML、CSV/IDoc → 结构体，字段改名、拼串、日期格式化），Cloud Integration 提供图形映射器：左边源结构、右边目标结构，用鼠标拖线完成字段对应，比写脚本直观、可维护、还能走映射函数库（拼接、拆分、取子串、日期转换…）。

I4.5 三种手段怎么选

需求推荐手段理由
加/改几个固定值、加个请求头Content Modifier零代码，配置即得
从 XML 里抽一个节点当属性Content Modifier（XPath）一个表达式搞定
解析 / 组装 JSON、算金额、循环、条件分支Groovy ScriptJSON 无 XPath；编程最灵活
XML 结构间大量字段改名 / 重组 / 拼接Message Mapping可视化、可评审、可复用映射

I4.6 操作手顺：订单金额换算 iFlow（order-transform）

场景接 Fiori 手顺3 的 submitOrder 数据（书店 Bookshop）：入站 JSON 订单 → 脚本算出金额 → 回显验证。

  1. 新建 iFlow

    包 iflow_course → Add → Integration Flow，命名 order-transform，打开画布。

  2. 配置 Sender

    HTTPS，Address 填 /order。

  3. 添加 Script 步骤并粘贴脚本

    右侧步骤面板拖入 Script，选中后在配置区粘贴 I4.3 的脚本（素材包 scripts/order-transform.groovy 同款）。

  4. 配置 Receiver

    HTTP，Address https://postman-echo.com/post，Authentication None。

  5. 部署并测试

    Save → Deploy → 等 Started → 复制端点（应为 …/cxf/order）→ 用 Bookshop 的一本书下单：

    curl -s -X POST "<ENDPOINT>" \
  -H 'Content-Type: application/json' \
  -d '{"book":1,"title":"Wuthering Heights","qty":2,"price":11.11}' \
  | python3 -m json.tool

  6. 验证

    回显的 data 应为 {"book":1,"title":"Wuthering Heights","qty":2,"amount":22.22,"status":"OK"}——脚本算出的 amount 就是 iFlow 的「增值」；同时 headers.x-amount 里能看到 22.22（脚本设的 header）。再进 MPL 确认 Completed。

⚠️ 脚本报错怎么看 脚本有语法/运行时错误时，调用会 Failed，MPL 里展开到 Script 步骤能看到异常栈（groovy.lang.MissingMethodException、JsonParseException 等）。八成是三类：JSON 字段名拼错、类型转换失败、忘了 return message。改完脚本 → Save → 重新 Deploy → 再调一次。
