I6.1 iFlow 清单与测试要点

iFlow（章节）Sender 地址做什么用什么载荷测看哪里验证
hello-echo（I3） /hello Content Modifier 替换 body + 加 header，转发回显 任意 JSON（会被整个换掉） 回显 data / headers.x-course
order-transform（I4） /order Groovy 算金额并重组 JSON order-book.json 回显 data.amount / headers.x-amount
order-dispatch（I5） /dispatch 按 <type> 分流加急 / 普通 order-urgent.xml / order-normal.xml 回显 headers.x-route + MPL 分支轨迹
📌 端点 URL 公式 三个 iFlow 部署后各自的端点为 https://<你的租户域名>/cxf/<上面的地址>，例如 https://xxxxx-tmn.eu10.hana.ondemand.com/cxf/order。租户域名见浏览器地址栏；也可在 Monitor → Manage Integration Content 点开 iFlow 复制。

I6.2 入站载荷

① order-book.json（I4，下单 JSON，沿用 Bookshop 的《Wuthering Heights》）

{"book":1,"title":"Wuthering Heights","qty":2,"price":11.11}

预期出站（回显 data，由脚本计算生成）：

{"book":1,"title":"Wuthering Heights","qty":2,"amount":22.22,"status":"OK"}

② order-urgent.xml / order-normal.xml（I5，分流测试，无命名空间便于教学）

<?xml version="1.0" encoding="UTF-8"?>
<order>
  <no>ORD-2002</no>
  <type>urgent</type>
  <customer>ACME</customer>
</order>
<?xml version="1.0" encoding="UTF-8"?>
<order>
  <no>ORD-1001</no>
  <type>book</type>
  <customer>ACME</customer>
</order>

带命名空间的真实版本只需给 XPath 加前缀（I5.6）：

<?xml version="1.0" encoding="UTF-8"?>
<order xmlns="http://acme.com/order">
  <no>ORD-3003</no>
  <type>urgent</type>
</order>

对应 Content Modifier 的 XPath 面板里声明前缀 ns1 → 值写 /ns1:order/ns1:type。

I6.3 Groovy 脚本

① order-transform.groovy（I4 完整版）

import com.sap.gateway.ip.core.customdev.util.Message
import groovy.json.JsonSlurper
import groovy.json.JsonOutput
import java.math.RoundingMode

def Message processData(Message message) {
    def body = message.getBody(java.lang.String) as String
    def order = new JsonSlurper().parseText(body)

    def amount = (order.price as BigDecimal)
        .multiply(new BigDecimal(order.qty as Integer))
        .setScale(2, RoundingMode.HALF_UP)

    def out = [
        book: order.book as Integer,
        title: order.title as String,
        qty: order.qty as Integer,
        amount: amount,
        status: 'OK'
    ]
    message.setBody(JsonOutput.toJson(out))
    message.setProperty('computedAmount', amount.toString())
    message.setHeader('X-Amount', amount.toString())
    return message
}

I6.4 curl 速查

# 通用：把下面的 <URL> 换成各自端点，文件换成 payloads/ 里的载荷
curl -s -X POST "<URL>" -H 'Content-Type: application/json' \
  --data-binary @payloads/order-book.json | python3 -m json.tool

curl -s -X POST "<URL>" -H 'Content-Type: text/xml' \
  --data-binary @payloads/order-urgent.xml | python3 -m json.tool

# 不带文件直接内联（I3 hello-echo）
curl -s -X POST "<URL>" -H 'Content-Type: application/json' \
  -d '{"ping":"pong"}' | python3 -m json.tool

没有 Python 就删掉末尾的 | python3 -m json.tool，直接看原始 JSON；Windows 可用 Postman（方法、URL、Headers、Body 与 curl 一一对应）。

I6.5 MPL 状态与常见错误速查

MPL / 部署状态含义常见原因与处理
Completed消息全程处理成功—
Failed处理中断，MPL 轨迹里有红色组件点开轨迹看具体步骤与异常栈（见下）
Retrying接收方瞬时失败，正在按重试策略重试多数等一会儿自动变 Completed / Failed
Error（部署状态）iFlow 部署失败多为配置缺漏：Receiver 没填地址、脚本编译不过、两个节点重名
脚本步骤 FailedMissingMethodException / ClassCastException / JsonParseException方法名写错 / 类型转换错 / 入站 JSON 不是预期结构。改脚本 → Save → 重新 Deploy → 再调
Receiver 步骤 Failed连接 / TLS / 鉴权错误回显服务偶发不可达：重试或换 https://httpbin.org/post；真实系统则查地址、网络策略与凭据（Security Material）
调用直接 401Sender 安全设置拦了匿名请求教学把 Sender Security 的 Authentication 设为 None（仅限教学，I3.7）
