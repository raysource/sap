第 I1 章：Integration Suite 概述

SAP Integration Suite（前身 CPI / HCI）· Cloud Integration 与 iFlow——本课程第一条「集成中间件」路线

前面三条路线在做同一件事：造一个能增删改查的业务应用（RAP 在 S/4HANA 里、CAP 在云端，Fiori 是它们共同的界面）。本路线换一个视角——把已有系统连起来：在 SAP Integration Suite 的 Cloud Integration（社区俗称 CPI，前身 SAP Cloud Platform Integration / HCI）里用浏览器画一个 iFlow（Integration Flow，集成流），让消息从一个系统流向另一个系统，中途还能被改写、转换、分流。

SAP Integration Suite Cloud Integration / CPI iFlow 适配器 Message Processing Log BTP

I1.1 Integration Suite 是什么

SAP Integration Suite 是 SAP BTP 上的集成平台（iPaaS），把 SAP 多年来散落各处的集成产品收进一个套件。它不止一个产品，而是按「连接方式」分了几大能力：

🔄 Cloud Integration

消息级集成（本课程主线）。画 iFlow 做系统间消息传递、转换、路由；支持 HTTP(S)、OData、SOAP、Mail、SFTP、Kafka 等适配器。

🗝️ API Management

API 级集成。把后端服务发布成受管的 API：代理、限流、鉴权、策略、开发者门户。

🧩 Open Connectors

面向非 SAP 云服务的现成连接器（Salesforce、Slack、Workday…），免写适配器。

📨 Event Mesh

事件驱动集成：系统间解耦的事件总线（Pub/Sub）。

🤝 Trading Partner Management

B2B / EDI（如 X12、EDIFACT）与贸易伙伴管理。

🧠 Integration Advisor

AI 辅助的映射与接口库：从历史集成中推荐字段映射、生成接口模型。

本培训只做第一块 Cloud Integration——它是 Integration Suite 的根基，也是「iflow」这个词的出处。其余能力属于进阶主题，不在本课程范围。

I1.2 为什么需要集成中间件（与 RAP / CAP 的分工）

RAP / CAP 解决的是「应用内」问题：数据模型、业务逻辑、服务暴露。但真实企业里系统是一堆孤岛：S/4HANA、第三方 SaaS、自己的 CAP 应用、遗留系统，它们各自的协议与数据格式都不一致。集成中间件站在孤岛之间做翻译与调度：

维度 RAP CAP Integration Suite（Cloud Integration）
回答的问题在 S/4HANA 内如何建模与暴露业务对象在云上如何快速开发业务服务系统之间如何传消息、转格式、定路由
产物CDS + Behavior + OData 服务CDS 模型 + srv handler + ODataiFlow（集成流），部署在 Cloud Integration 租户
运行位置S/4HANA 内部本地 / BTP Cloud FoundryIntegration Suite 租户（BTP 上独立的运行时）
面向谁ABAP 开发者全栈 / 云开发者集成开发者（Integration Developer）

三者不是三选一，而是分层配合。一条典型的真实链路：S/4HANA 用 RAP 把采购订单暴露成 OData → CPI 的 iFlow 定时拉取并转换成 JSON → 推给 SAP 之外的第三方系统，或反过来接收外部订单写入 CAP 应用。Integration Suite 是你前几条路线成果的「外联管道」。

📌 术语提醒 这家的改名史：HCI（Hana Cloud Integration）→ SAP Cloud Platform Integration（CPI） → 归入 SAP Integration Suite 的 Cloud Integration 能力。社区至今口语叫 CPI，本课程「CPI」与「Cloud Integration」混用，指同一个东西。

I1.3 iFlow 是什么——先看最小集成流

一个 iFlow 是装在 Integration Package（集成包）里的可视化消息流：消息从 Sender（发送方适配器）进来，经过一串处理步骤，从 Receiver（接收方适配器）出去。最简单的「Hello World」长这样：

iFlow 编辑画布 — hello-echo（Cloud Integration）
📦 集成包✏️ hello-echo👁 部署状态
⬇️ Sender
适配器 HTTPS · 地址 /hello
✎Content Modifier
作用 改写消息体 / 加请求头
⬆️ Receiver
适配器 HTTP · 目标 https://postman-echo.com/post
图 I1-1 最小 iFlow：HTTP 调用者 → HTTPS Sender 接收 → Content Modifier 改写消息 → HTTP Receiver 转发出去；箭头即消息流

围绕这张图，需要先建立四个概念：

概念说明本课程出现章节
Integration PackageiFlow 的「收纳盒」，带命名空间（Technical Name）；同主题的流、脚本、映射放在一个包里I3
Sender / Receiver 适配器流的入口与出口，决定协议：HTTPS/HTTP、SOAP、OData、Mail、SFTP…I3
处理步骤消息流中间的可视化加工：Content Modifier（改写）、Script（Groovy）、Message Mapping（字段映射）、Router / Content-Based Router（分流）…I3–I5
消息三件套每条消息 = Body（正文）+ Headers（随协议传输的请求头）+ Properties（只在流内部传递的交换属性）I3 / I4
MPLMessage Processing Log：每次运行留下的日志，可逐步骤查看成功/失败——CPI 里最重要的排错入口I3 / I6

I1.4 在哪里开发：Cloud Integration Web UI

iFlow 的开发、部署、监控全在浏览器里的 Cloud Integration Web UI（租户地址形如 https://<租户ID>-tmn.<区域>.hana.ondemand.com），不需要装任何本地工具。主界面分四大区：

🔍 Discover

浏览 SAP 官方集成包与模板（Integration Package 市场），可整包「复制到工作区」再改造——入门最快的方式。

✏️ Design

开发区：建集成包、画 iFlow、写脚本与映射。本课程 I3–I5 主要在这里。

👁 Monitor

监控区：Manage Integration Content（已部署 iFlow 与端点）、Message Processing Log（运行日志）、消息队列等。

🔑 安全材料

Security Material：凭据（Basic / OAuth2）、证书、密钥库——接收方要鉴权时在这里存密码。

I1.5 前置与环境

  • 唯一硬性要求：一个能开通 Integration Suite 的 SAP BTP 账号（Trial 或企业 Free Tier 均可），见 I2 环境准备；如果已经跟过 BTP 路线，同一个子账号直接复用。
  • 不需要本地安装：所有操作在浏览器完成；测试用 Postman 或 curl（终端即可）。
  • 知识衔接：理解 CAP 的 OData 概念即可（I5 会涉及 XML/XPath 基础）。

I1.6 本路线学习路径

  1. 环境准备BTP 开通 Integration Suite + 角色
  2. 手顺1：第一个 iFlowHTTPS → Content Modifier → HTTP，部署 + Postman 验证
  3. 手顺2：消息转换Content Modifier 深挖 / Groovy Script / Message Mapping
  4. 手顺3：内容路由属性 + Content-Based Router 按订单类型分流
  5. 测试数据与素材样例载荷 / 脚本 / curl 速查
