1. CAP Node.js 工程（samples/cap-bookshop）

对应《CAP 手顺1–4》+ 第7章测试数据

可直接运行的 Bookshop 工程。下载全部文件后放进同一目录，保持目录结构不变即可。

文件内容
package.json依赖（@sap/cds）+ start/watch 脚本
.cdsrc.json配置：本地 SQLite
db/schema.cds数据模型：Genres / Authors / Books / Orders
srv/cat-service.cds服务定义：Books 可写 + submitOrder Action
srv/cat-service.js业务逻辑：库存校验、畅销标记、日志
db/data/…-Genres.csv种子数据：5 个分类（201–205）
db/data/…-Authors.csv种子数据：4 位作者（101–104）
db/data/…-Books.csv种子数据：10 本书（库存含 0 / 100 / 333 边界值）
db/data/…-Orders.csv种子数据：2 条订单
README.md运行手顺 + curl 测试命令 + 与教程的两处差异

快速开始

cd cap-bookshop
npm install
npm start            # 或 cds watch，热重载
# 打开 http://localhost:4004 浏览；详细 curl 测试见 README.md

⚠️ 使用注意

📌 与教程页面的差异 / 使用注意
  • CAP Node：教程页面展示的 cat-service.cds 把 Books 标为 @readonly，但第7章测试场景要对 Books 做 POST/PATCH/DELETE。素材包让 Books 可写，并在 README 中说明。
  • CAP Node：submitOrder 的参数用 book: Integer 而非 book: Books，以匹配文档化 curl 请求体 {"book":1,"quantity":2}。
  • RAP：rejecttravel 教程只声明未给实现；素材包按 accepttravel 的 EML 模式补全（状态改 X）。另外 validateCustomer 依赖 ZCUSTOMER 演示表，请先建表并录入客户 1–4。
  • BTP：源码与 SQL 里的主机 / 口令 / ngdbc 版本号均为占位符（详见包内 README 速查表），连接前务必替换；HANA Cloud 的 JDBC URL 请保持 encrypt=true&validateCertificate=true。
  • Fiori：前端素材需配合 CAP Bookshop 工程（samples/cap-bookshop）使用；对象页「订单」子表依赖服务暴露 Orders（素材包已含）；F4 状态徽标需按包内 README 在服务端补 criticality 字段，直接启用会有运行时错误。
  • CAP + Fiori 整体工程：criticality 已在服务端实现，徽标开箱即用；与拆分包的差异是它把后端投影加了 criticality 计算字段（见 srv/cat-service.cds），其余逻辑与 cap-bookshop 一致。
