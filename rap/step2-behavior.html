第 4 章：手顺2 — 行为定义与实现

Behavior Definition（BDEF）+ 实现类 + Action / 校验

数据模型只解决了「读」。本章给它加上行为：声明增删改、自定义 Action（批准/拒绝）、保存校验，并用 EML 在 ABAP 实现类里落地。完成后 Travel 就是一个真正可用的业务对象。

BDEF Behavior Pool EML with draft validation

4.1 行为层是什么

行为定义（BDEF，Behavior Definition）用声明式语法描述「一个实体支持哪些操作」：

  • 标准操作：create / update / delete（增删改）。
  • 自定义 Action：如「批准旅行」「拒绝旅行」，带参数/返回结果。
  • 校验 validation：在 on save 时检查业务规则。
  • 锁定与并发：lock master（行锁）、etag master（乐观锁，防并发覆盖）。
  • 草稿：with draft 让编辑先落草稿表，保存才写正式表。

4.2 新建行为定义

右键接口视图 Core Data Services → New → Behavior Definition（或在 Project Explorer 选中 ZI_TRAVEL 后直接 New → Behavior Definition），名称自动取 ZI_TRAVEL。把生成的模板替换为：

managed implementation in class zbp_i_travel unique;
strict ( 2 );
with draft;

define behavior for ZI_Travel alias Travel
persistent table ztravel
lock master
authorization master ( instance )
etag master LastChangedAt

field ( readonly : update ) TravelID, CreatedBy, CreatedAt, LastChangedBy, LastChangedAt;
field ( mandatory : create ) CustomerID, AgencyID, BeginDate, EndDate;

create;
update;
delete;

action ( features : instance ) AcceptTravel result [1] $self;
action ( features : instance ) RejectTravel result [1] $self;

validation validateCustomer on save { field CustomerID; }

mapping for ztravel
{ TravelID = travelid; AgencyID = agencyid; CustomerID = customerid; }

关键语法逐行解释

关键字含义
managed托管实现：create/update/delete 的持久化由框架自动完成，实现类只需写 Action/校验/Determination
implementation in class zbp_i_travel指向行为实现类（Behavior Pool），unique 表示 BDEF 与类一对一
strict ( 2 )启用 Strict 模式第二版，语法更严格、行为更规范（S/4HANA 2020+）
with draft开启草稿：前端编辑写入草稿表，保存才写 ztravel（草稿表由系统自动生成）
persistent table ztravel声明持久化表，managed 模式下框架据此做数据库读写
lock master由根实体统一管理整棵对象树的锁（行级）
authorization master ( instance )实例级权限控制（可按记录做 PFCG 授权）
etag master LastChangedAt乐观锁标记字段：并发更新时用 LastChangedAt 比对，防止丢更新
field ( readonly : update )字段级约束：这些字段在 update 时只读
field ( mandatory : create )字段级约束：create 时必填
action ( features : instance )声明实例级 Action，并用 get_features 动态控制按钮可用性
validation … on save保存时校验，字段变更才触发；本例校验 CustomerID
mapping for ztravel把 CDS 视图字段映射到物理表字段（视图别名与表字段名不同时需要）

4.3 生成实现类 zbp_i_travel

激活 BDEF 前，双击第 1 行的 implementation in class zbp_i_travel 超链接，Eclipse 会弹出 Create Class 向导，点 Next → Finish 生成一个空的行为池类。类内自动包含根实体的局部类 lhc_travel（继承自 cl_abap_behv_handler）；若将来把子实体 Booking 也纳入行为定义，会再生成 lhc_booking。

4.4 实现核心方法

方法写在局部类 lhc_travel 里。先声明方法清单（接口与 ABAP 实现一一对应）：

CLASS lhc_travel DEFINITION INHERITING FROM cl_abap_behv_handler.
  PRIVATE SECTION.

    METHODS get_features FOR FEATURES
      IMPORTING keys REQUEST requested_features FOR travel
      RESULT result.

    METHODS accepttravel FOR MODIFY
      IMPORTING keys FOR ACTION travel~AcceptTravel.

    METHODS rejecttravel FOR MODIFY
      IMPORTING keys FOR ACTION travel~RejectTravel.

    METHODS validatecustomer FOR VALIDATION ON SAVE
      IMPORTING keys FOR travel~validateCustomer.
ENDCLASS.

4.4.1 get_features —— 控制按钮可用性

返回 %action-… 的启用状态：例如「已拒绝」的旅行不能再批准，「已批准」的不能再拒绝。

METHOD get_features.
  READ ENTITIES OF z_i_travel IN LOCAL MODE
    ENTITY travel
      FIELDS ( Status )
      WITH CORRESPONDING #( keys )
    RESULT DATA(travels)
    FAILED    DATA(failed).

  result = VALUE #( FOR travel IN travels
    LET status = travel-Status IN
    ( %tky                 = travel-%tky
      %action-AcceptTravel = COND #( WHEN status = if_abap_behv_status=>status_rejected
                                     THEN if_abap_behv=>fc-o-disabled
                                     ELSE if_abap_behv=>fc-o-enabled )
      %action-RejectTravel = COND #( WHEN status = if_abap_behv_status=>status_approved
                                     THEN if_abap_behv=>fc-o-disabled
                                     ELSE if_abap_behv=>fc-o-enabled ) ) ).
ENDMETHOD.

4.4.2 AcceptTravel —— 用 EML 更新状态

METHOD accepttravel.
  MODIFY ENTITIES OF z_i_travel IN LOCAL MODE
    ENTITY travel
      UPDATE FIELDS ( Status )
        WITH VALUE #( FOR key IN keys ( TravelID = key-TravelID
                                        Status   = if_abap_behv_status=>status_approved ) )
    REPORTED DATA(rs)
    FAILED DATA(rf).

  reported = corresponding #( deep rs ).
  failed   = corresponding #( deep rf ).

  IF rf IS INITIAL.
    reported-travel = VALUE #(
      FOR row IN rs-travel
        ( %tky = row-%tky
          %msg = new_message_with_text(
            severity = if_abap_behv_message=>severity-success
            text     = '已批准' ) ) ).
  ENDIF.
ENDMETHOD.

4.4.3 validateCustomer —— 保存校验

校验客户是否存在：MODIFY 保存前框架调用 validateCustomer，失败时把 %msg 写进 reported-travel，保存被阻断。本例假设存在一张客户主数据表 ZCUSTOMER（含字段 customerid），可自行创建或用演示客户表替换。

METHOD validatecustomer.
  READ ENTITIES OF z_i_travel IN LOCAL MODE
    ENTITY travel
      FIELDS ( CustomerID )
      WITH CORRESPONDING #( keys )
    RESULT DATA(travels).

  IF travels IS NOT INITIAL.
    SELECT customerid FROM zcustomer
           FOR ALL ENTRIES IN @travels
           WHERE customerid = @travels-customerid
           INTO TABLE @DATA(valid_ids).

    LOOP AT travels INTO DATA(travel).
      IF NOT line_exists( valid_ids[ customerid = travel-customerid ] ).
        APPEND VALUE #( %tky = travel-%tky ) TO failed-travel.
        APPEND VALUE #( %tky = travel-%tky
                        %msg = new_message_with_text(
                          severity = if_abap_behv_message=>severity-error
                          text     = |客户 { travel-CustomerID } 不存在| ) )
          TO reported-travel.
      ENDIF.
    ENDLOOP.
  ENDIF.
ENDMETHOD.

4.5 EML 三件套

EML（Entity Manipulation Language）是行为实现类里读写业务对象的标准语法，核心是 reported / failed / mapped 三件套：

  • READ ENTITIES / MODIFY ENTITIES —— 读/改；IN LOCAL MODE 表示在自身行为池内直接操作，不重复触发行为。
  • %tky —— 实体「技术键」（主键 + %is_draft 等），跨 draft 操作记录身份。
  • reported —— 回传消息（成功/错误/警告），供 UI 展示。
  • failed —— 标记失败实体，框架据此终止保存/事务。
  • mapped —— 返回 create 时新生成键（如自增 ID），本次未用到。

4.6 操作手顺

  1. 新建行为定义

    选中 ZI_TRAVEL 右键 New → Behavior Definition，粘贴 4.2 节BDEF 代码。

  2. 生成实现类

    双击 BDEF 中 implementation in class zbp_i_travel 超链接 → Create Class → Finish。此时类还是空的。

  3. 激活 BDEF

    Ctrl+F3 激活。激活时系统自动生成草稿相关结构（Z…_D）与锁定对象，若有报错按提示修正（通常是 mapping 或 strict 语法）。

  4. 编写实现类

    在 zbp_i_travel 里补上 4.4 节的方法定义与实现（get_features、accepttravel、rejecttravel、validatecustomer），激活类。

  5. 验证

    右键 ZI_TRAVEL 行为定义 → Open With → Data Preview 能看到「行为」列；或进入 手顺3 暴露为 OData 后到 Fiori 里点按钮。

✅ 验证/结果 BDEF 与实现类均激活；get_features 让已批准行「批准」按钮置灰；Data Preview 中可对行执行 AcceptTravel，状态从 N 新 变 A 已批准。
💡 注意点
  • 同包约束：实现类必须在 BDEF 所在的包（ZRAP_TRAINING）内，否则激活报错。
  • 激活顺序：先激活 BDEF 前需先激活实现类壳；方法体变更后再次激活类即可，无需重激活 BDEF（除非改了声明）。
  • unique：表示实现类仅被这一个 BDEF 使用；多个 BDEF 共用需去掉 unique。
  • Draft 表：with draft 会按持久表自动生成草稿结构，你在 Project Explorer 的「数据库视图/草稿」下能看到它们，不要手动删除。
  • 消息文本：new_message_with_text 适用于简单文本；生产环境建议用消息类（new_message + Message Number）便于 i18n。
