第 5 章：手顺3 — 服务定义与绑定

Service Definition + Service Binding → 生成 OData V4 服务

业务对象此刻还是「系统内」的对象。本章把它发布为对外可访问的 OData V4 服务：先声明服务定义（暴露哪些实体），再建服务绑定（选择 OData V4 协议），拿到一个可被 Fiori 和外部系统消费的 URL。

Service Definition Service Binding OData V4 /sap/opu/odata4

5.1 服务层两个对象

① Service Definition

声明式定义「服务暴露哪些 CDS 实体」，用 expose 语句。它只做暴露范围的裁剪，不实现任何逻辑。

② Service Binding

把服务定义「绑」到一个协议（OData V2 / V4 / Web API / InA）上，产生运行时 URL。一个服务定义可被多个 Binding 以不同协议暴露。

💡 expose 的选择 应该暴露接口视图（ZI_）或经过授权的消费视图/投影，而不是直接把内部物理表暴露给外部——表结构没有语义、也绕过了 CDS 的授权与类型封装。本培训暴露 ZI_TRAVEL 与 ZI_TRAVEL_BOOKING 两个接口视图。

5.2 新建服务定义 ZUI_TRAVEL_O4

右键 Core Data Services → New → Service Definition，名称 ZUI_TRAVEL_O4，替换模板为：

@EndUserText.label: 'Travel OData 服务定义'
define service ZUI_TRAVEL_O4 {
  expose ZI_TRAVEL as Travel;
  expose ZI_TRAVEL_BOOKING as Booking;
}

5.3 新建服务绑定 ZUI_TRAVEL_O4

右键该服务定义 New → Service Binding，名称仍用 ZUI_TRAVEL_O4，Binding Type 选 OData V4 – UI（供 Fiori 消费；若给第三方系统也可选 OData V4）。创建后激活绑定：

5.4 Service URL 各段含义

http://d4h:8000/sap/opu/odata4/sap/zuiv4travel_o4/srvd/sap/zui_travel_o4/0001/
URL 段含义
/sap/opu/odata4OData V4 服务的基础路径（V2 是 /sap/opu/odata）
zuiv4travel_o4系统自动生成的运行时服务名（内部名）
/srvd/表示后面是 Service Definition 路径
zui_travel_o4你的服务定义名称
0001服务版本号（version.active 注解决定）

5.6 操作手顺

  1. 新建服务定义 ZUI_TRAVEL_O4

    Core Data Services → New → Service Definition，粘贴 5.2 节代码并激活。

  2. 新建服务绑定 ZUI_TRAVEL_O4

    右键服务定义 → New → Service Binding，名称 ZUI_TRAVEL_O4，Binding Type 选 OData V4 – UI。

  3. 激活绑定

    Ctrl+F3 激活。激活后右侧出现 Service URL，实体树的 Create/Update/Delete/Action 节点列出服务的全部能力。

  4. 验证服务文档

    浏览器打开 Service URL，确认返回含 Travel / Booking 的服务文档 XML。

  5. 进入预览

    在 Service Binding 中点 Preview 按钮，进入下一章的 Fiori 预览（需 Fiori 运行时 BSP 应用已激活）。

✅ 验证/结果 Service Definition 与 Binding 均激活；浏览器访问 Service URL 返回 XML 服务文档；实体树展开可见 AcceptTravel / RejectTravel 两个 Action 已自动暴露。
💡 注意点
  • expose 对象类型：Service Definition 只能 expose CDS 视图/实体，不能直接 expose 普通数据库表；把表直接暴露会报错。
  • 命名规范：服务对象用 ZUI_ 前缀（User Interface 服务）+ _O4 后缀（OData V4），一眼可辨协议。
  • OData V4 vs V2：V4 是 REST 风格更强的新一代协议（支持 $expand 简化、$count 内联等）；V2 用于老 Fiori / 第三方集成。本培训全程 V4。
  • Preview 依赖：Preview 会打开 Fiori Elements，需要系统已激活 /sap/bc/ui5_ui5 等 Fiori BSP 运行时；开发环境一般默认开启。

    A. 选择数据库
    B. 声明把哪些实体（消费视图）及操作暴露给外部

    A. 跑批任务
    B. Fiori 预览与注解化 UI

    D. 写 Groovy

  4. 服务 URL 中 /0001/ 这一段表示？

    A. 端口号
    B. 服务版本号（默认从 0001 起）

    C. 一个函数库

  8. 服务定义与绑定可以是一对多吗？

    A. 可以：同一份定义可建多个绑定（不同协议 / 用途）
    B. 不可以，必须一一对应
    C. 最多两个绑定
    D. 绑定只能建一次
答案与解析（🟢 基础巩固（1–8））
题号答案解析
1A服务定义声明暴露内容，服务绑定选择协议并发布 URL。
2B服务定义划定对外边界：define service … { expose … }。
3BUI 类型的绑定生成面向 Fiori Elements 的注解服务并支持预览；Web API 类型则面向系统集成。
4B版本段随服务定义发布而存在；通常从 0001 开始，发布新版本会得到新的版本段。
5A路径最后一段是实体集名，OData 客户端对它做 CRUD 与筛选。
6A$metadata 返回服务模型 XML，是最快的连通性验证。
7BAction 属于实体行为：服务定义暴露实体 → 绑定发布 → OData 客户端即可调用该实例动作。
8A定义是契约，绑定是发布方式；同一契约可按需多协议发布。

  4. 关于服务 URL 的版本段说法正确的是？

    A. 固定为 0000
    B. 默认从 0001 起，随定义发布新版本而存在多版本 URL
    C. 随机生成
    D. 等于系统号
答案与解析（🔶 能力提高（9–12））
题号答案解析
9Bodata4 是 V4 的网关路径（odata2 对应 V2）；配合 /srvd/…/0001 可整体理解服务定位。
10A同一服务契约按消费方选择发布形态：给人（Fiori）用 UI 型，给系统用 Web API 型。
11B协议绑定在绑定对象上；定义可复用，新增 / 更换绑定即可发布别的协议。
12B版本段从 0001 开始按发布递增，多版本可并存，旧客户端不因新版本发布而失效。
