第 3 章：手顺1 — CDS 数据模型

数据库表 → 接口视图 ZI_TRAVEL → 消费视图 ZC_TRAVEL

RAP 的一切从数据模型开始。本章创建业务对象 Travel 的底层物理表 ZTRAVEL / ZTRAVEL_BOOKING，再用 CDS 视图搭出「接口视图 + 消费视图」的视图栈。

3.1 视图栈：接口视图 vs 消费视图

RAP 推荐用两层视图承载数据模型，职责分离：

维度接口视图（Interface View）消费视图（Consumer / Projection View）
命名ZI_ 开头（Interface）ZC_ 开头（Consumption）
职责数据源头：语义完整、暴露给上层消费按场景裁剪 / 重命名 / 加 UI 注解
能否被 Behavior 引用✅ 是（BDEF 定义在接口视图上）❌ 通常不直接承载行为
能否被 Service 暴露✅ 是（推荐）✅ 是（经授权投影）
💡 为什么分两层？ 接口视图是「模型的真相」——业务对象定义在它上面；消费视图是「场景的窗口」——不同 UI / 服务按需投影。改接口视图影响所有消费者，改消费视图只影响自己的场景。

3.2 新建数据库表 ZTRAVEL

在包 ZRAP_TRAINING 上右键 New → Other… → Database Table，名称 ZTRAVEL。字段如下（MANDT 由 ADT 在设置 Client Handling 时自动添加）：

字段键数据类型长度说明
MANDT☑CLNT3客户端（自动添加）
TRAVELID☑INT25旅行编号（主键）
AGENCYIDINT25旅行社 ID

BEGINDATEDATS8开始日期
ENDDATEDATS8结束日期

3.3 新建 CDS 接口视图 ZI_TRAVEL

右键 Core Data Services → New → Data Definition，勾选 Add a type or entity，模板选 Define View Entity（CDS view entity），名称 ZI_TRAVEL。把生成的模板替换为下面内容并激活（Ctrl+F3）：

@EndUserText.label: 'Travel - 接口视图'
@AccessControl.authorizationCheck: #CHECK
@Metadata.ignorePropagatedAnnotations: true
@ObjectModel.usageType:{
  serviceQuality: #X,
  sizeCategory: #S,
  dataClass: #MIXED
}
define root view entity ZI_TRAVEL as select from ztravel
{
  key travelid            as TravelID,
      agencyid            as AgencyID,
      customerid          as CustomerID,
      begindate           as BeginDate,
      enddate             as EndDate,
      bookingfee          as BookingFee,
      totalprice          as TotalPrice,
      currencycode        as CurrencyCode,
      status              as Status,
      description         as Description,
      createdby           as CreatedBy,
      createdat           as CreatedAt,
      lastchangedby       as LastChangedBy,
      lastchangedat       as LastChangedAt
}

3.4 新建消费视图 ZC_TRAVEL

同样在 Core Data Services → New → Data Definition，模板这次选 Projection View，名称 ZC_TRAVEL。投影视图不重新定义数据，只从接口视图选择字段：

@EndUserText.label: 'Travel - 消费视图'
@AccessControl.authorizationCheck: #CHECK
@Metadata.ignorePropagatedAnnotations: true
projection on ZI_TRAVEL
{
  key TravelID,
      AgencyID,
      CustomerID,
      BeginDate,
      EndDate,
      BookingFee,
      TotalPrice,
      CurrencyCode,
      Status,
      Description,
      CreatedBy,
      CreatedAt,
      LastChangedBy,
      LastChangedAt
}

激活后，右键 ZC_TRAVEL 可在 Open With → Data Preview 中直接看到数据（此时表还是空的）。

3.5 预订子实体接口视图 ZI_TRAVEL_BOOKING

第 5 章的服务定义要同时暴露 Travel 与其预订明细，因此再补一个预订的接口视图（模板同 3.3，选 Define View Entity）：

@EndUserText.label: 'Travel Booking - 接口视图'
@AccessControl.authorizationCheck: #CHECK
@Metadata.ignorePropagatedAnnotations: true
@ObjectModel.usageType:{
  serviceQuality: #X,
  sizeCategory: #S,
  dataClass: #MIXED
}
define root view entity ZI_TRAVEL_BOOKING as select from ztravel_booking
{
  key travelid       as TravelID,
  key bookingid      as BookingID,
      bookingdate    as BookingDate,
      customerid     as CustomerID,
      carrierid      as CarrierID,
      connectionid   as ConnectionID,
      flightdate     as FlightDate,
      flightprice    as FlightPrice,
      currencycode   as CurrencyCode,
      bookingstatus  as BookingStatus
}

3.6 用 SQL Preview 验证

激活无错误后，右键 ZI_TRAVEL → Open With → SQL Preview，ADT 会展示该视图实际生成的 SELECT 语句——这是验证视图定义是否正确的最快方式。

3.7 操作手顺

  1. 创建数据库表 ZTRAVEL

    右键包 ZRAP_TRAINING → New → Other… → Database Table，名称 ZTRAVEL，按 3.2 节字段清单建列，Ctrl+F3 激活。CURR 字段需在其 Reference Table/Field 指定 CURRENCYCODE。

  2. 创建子表 ZTRAVEL_BOOKING

    同样方式建 ZTRAVEL_BOOKING，联合主键 TRAVELID + BOOKINGID，激活。

  3. 创建接口视图 ZI_TRAVEL

    Core Data Services → New → Data Definition，模板 Define View Entity，粘贴 3.3 节DDL 并激活。

  4. 创建消费视图 ZC_TRAVEL

    模板换 Projection View，粘贴 3.4 节代码并激活。

  5. 创建预订接口视图 ZI_TRAVEL_BOOKING

    复制 3.5 节代码，激活。

  6. 验证 SQL Preview

    右键 ZI_TRAVEL → Open With → SQL Preview，确认生成 SELECT 无错误；ZC_TRAVEL → Open With → Data Preview 可打开空表。

✅ 验证/结果 三个视图（ZI_TRAVEL、ZC_TRAVEL、ZI_TRAVEL_BOOKING）均激活、状态为绿色；SQL Preview 能生成 SELECT；Data Preview 打开不报错。
💡 注意点
  • 命名规范：用户对象一律 Z 开头；接口视图 ZI_、消费视图 ZC_、表直接 ZT 开头，避免与 SAP 对象冲突。
  • 激活顺序：先激活表，再激活依赖它的视图；视图激活失败多半是上游表未激活。
  • 授权对象：@AccessControl.authorizationCheck: #CHECK 表示受权限检查；如需无权限限制可改 #NOT_REQUIRED（生产不建议）。
  • #MIXED：dataClass: #MIXED 表示数据量中等、读多写少混合访问，用于 HANA 表分区/存储优化提示；serviceQuality: #X 表示关键业务数据。
  • 主键类型：本培训用 INT2 便于手输数据；真实项目常用 UUID（SYSAPOID / RAW16）做主键。
  • CURR / CUKY 配对：每个 CURR 字段必须有对应的 CUKY 参考字段，否则金额无法按币种小数位换算。
