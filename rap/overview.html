第 1 章：RAP 概述

ABAP RESTful Application Programming Model · 现代 ABAP 开发的入口

RAP 是 SAP 在 S/4HANA 上构建云就绪 Fiori 应用的官方编程模型。它把「数据模型 + 业务逻辑 + 服务 + UI」组织成一个业务对象，用声明式方式替代传统「报表-屏幕」的瀑布式开发。

CDS 视图 Behavior OData V4 S/4HANA 2020+ ADT

1.1 RAP 是什么

RAP（ABAP RESTful Application Programming Model）是一套端到端的开发范式：从数据库表、CDS 数据模型，到业务行为（增删改、Action、校验），再到 OData 服务的暴露与 Fiori UI，全程在同一套工具（ADT）与同一套概念里完成。它建立在三个支柱之上：

① Core Data Services

数据模型层。用 CDS DDL 定义视图与关联，封装数据访问逻辑，屏蔽底层物理表结构。

② Behavior

业务逻辑层。用 BDEF 声明行为（create/update/delete、action、validation、determination），在实现类里写 ABAP。

③ OData Services

暴露层。用 Service Definition + Binding 把业务对象发布为 OData 服务，供 Fiori / 外部系统消费。

1.3 业务对象（Business Object）

RAP 的一切围绕业务对象展开。一个业务对象 = 一个 CDS 数据模型（含父子实体）+ 一套行为定义。它拥有一个唯一键、生命周期（Draft → Active → 归档）、以及与前端交互的标准操作。

1.5 Draft（草稿）机制

RAP 默认支持 with draft：用户在 Fiori 前端编辑时，数据先写入草稿表，点「保存」才写入业务表。这让编辑动作可以随时取消、不污染正式数据，也是 Fiori 交互「响应式/编辑即预览」体验的基础。

  • 草稿表：SAP 自动生成 Z..._D 结构，无需手动维护。
  • Draft 对上层透明：OData 请求 DraftEntity 与正式实体由框架自动切换。
  • 你只需要在 BDEF 里写 with draft 一行，框架搞定其余。
