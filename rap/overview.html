第 1 章：RAP 概述

ABAP RESTful Application Programming Model · 现代 ABAP 开发的入口

RAP 是 SAP 在 S/4HANA 上构建云就绪 Fiori 应用的官方编程模型。它把「数据模型 + 业务逻辑 + 服务 + UI」组织成一个业务对象，用声明式方式替代传统「报表-屏幕」的瀑布式开发。

CDS 视图 Behavior OData V4 S/4HANA 2020+ ADT

1.1 RAP 是什么

RAP（ABAP RESTful Application Programming Model）是一套端到端的开发范式：从数据库表、CDS 数据模型，到业务行为（增删改、Action、校验），再到 OData 服务的暴露与 Fiori UI，全程在同一套工具（ADT）与同一套概念里完成。它建立在三个支柱之上：

① Core Data Services

数据模型层。用 CDS DDL 定义视图与关联，封装数据访问逻辑，屏蔽底层物理表结构。

② Behavior

业务逻辑层。用 BDEF 声明行为（create/update/delete、action、validation、determination），在实现类里写 ABAP。

③ OData Services

暴露层。用 Service Definition + Binding 把业务对象发布为 OData 服务，供 Fiori / 外部系统消费。

1.3 业务对象（Business Object）

RAP 的一切围绕业务对象展开。一个业务对象 = 一个 CDS 数据模型（含父子实体）+ 一套行为定义。它拥有一个唯一键、生命周期（Draft → Active → 归档）、以及与前端交互的标准操作。

1.5 Draft（草稿）机制

RAP 默认支持 with draft：用户在 Fiori 前端编辑时，数据先写入草稿表，点「保存」才写入业务表。这让编辑动作可以随时取消、不污染正式数据，也是 Fiori 交互「响应式/编辑即预览」体验的基础。

  • 草稿表：SAP 自动生成 Z..._D 结构，无需手动维护。
  • Draft 对上层透明：OData 请求 DraftEntity 与正式实体由框架自动切换。
  • 你只需要在 BDEF 里写 with draft 一行，框架搞定其余。

    C. OData Services

    A. 纯过程式报表编程
    B. 声明式地组织「业务对象」
    C. 无框架的任意编码
    D. 前端拖拽生成 ABAP

  3. 在 RAP 中，一个「业务对象（Business Object）」通常由哪四部分组成？

    A. 表 + 报表 + 屏幕 + 菜单
    B. 类 + 接口 + 事件 + 字典

    A. 提升数据库查询性能

    A. 数据库存取优化
    B. 把业务对象对外发布为 OData 服务供 Fiori / 外部系统消费

    D. 权限角色管理

  6. 在消费视图上写 @UI 注解，主要驱动什么？

    A. 数据库索引
    B. 输入校验
    C. Fiori Elements 按元数据自动渲染列表 / 详情
    D. 触发后台作业

  7. RAP 相比传统 ABAP 开发（SE11/SE80 时代）最本质的变化是？

    A. 语言换成 JavaScript
    B. 去掉数据库层
    C. 用声明式 CDS / BDEF / 服务代替大量手写数据处理与 UI 代码
    D. 只允许云端部署
答案与解析（🟢 基础巩固（1–7））
题号答案解析
1D三支柱是 CDS + Behavior + OData；UI5 属于展示层（通常由 Fiori Elements 承担），不算 RAP 编程模型的支柱。
2BRAP 用 CDS 声明数据模型、用 BDEF 声明行为、用服务定义/绑定暴露 OData，整件事围绕一个「业务对象」展开。
3CRAP 业务对象 = 数据（CDS 视图栈）+ 行为（BDEF/实现类）+ 服务（定义/绑定）+ UI（Fiori Elements）。
4B草稿把未保存的编辑隔离在 Draft 表，支持校验与「激活」语义；这是 RAP/Fiori 编辑体验的关键。
5B服务定义声明「暴露哪些实体」，绑定选择协议（OData V4 等）并发布 URL——它们处于行为层之上、UI 之下。
6C@UI 注解进入 OData 元数据，Fiori Elements 据此自动生成页面结构，无需手写 UI5。
7C范式从「过程式手工建表建屏」转向「声明式模型 + 框架生成」，这是 RAP 的核心价值。

  3. RAP 强调「云就绪 / Clean Core」，其含义最接近哪一项？

    A. 只能在云上运行
    B. 所有代码写进 S/4 标准对象里
    C. 扩展 S/4HANA 时尽量走扩展点与自有对象，不修改标准对象，便于升级迁移
    D. 不使用任何 SAP 标准功能
答案与解析（🔶 能力提高（8–10））
题号答案解析
8ARAP 的卖点之一是「一套模型、两端就绪」：应用层一致，云上主要处理 CF/基础设施差异。
9B草稿与激活版本并存：编辑写 Draft，提交时校验并「激活」合并——正式数据不会出现半截编辑状态。
10CClean Core 指扩展不侵入标准内核，让 on-prem / 云升级都安全——RAP 对象建在自有包与扩展点正是为此。
