第 B7 章：手顺5 模式二 Maven

用 Maven 标准工程组织代码：archetype 生成骨架 → pom 声明 ngdbc → mvn compile exec:java

模式一让你看清 JDBC 的本质；模式二把工程交给 Maven 管理——依赖（ngdbc）写在 pom.xml 里自动下载，编译运行一条命令。这是 Java 开发者的标准姿势，也是模式三 Spring Boot 的地基。

Maven archetype pom.xml exec-maven-plugin ngdbc 依赖 mvn compile exec:java

B7.1 用 archetype 生成骨架

Maven 的 archetype:generate 按模板生成标准工程骨架。maven-archetype-quickstart 是最小 Java 工程；用 -D...=... 传参数、-DinteractiveMode=false 跳过交互提问：

cd projects

mvn archetype:generate \
  -DarchetypeGroupId=org.apache.maven.archetypes \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DarchetypeVersion=1.4 \
  -DgroupId=com.acme.bookshop \
  -DartifactId=bookshop-maven \
  -DinteractiveMode=false

cd bookshop-maven
BAS 终端 — archetype 生成
$ mvn archetype:generate -DarchetypeGroupId=org.apache.maven.archetypes ...
…
[INFO] BUILD SUCCESS
$ cd bookshop-maven && find src -type f
src/main/java/com/acme/bookshop/App.java
src/test/java/com/acme/bookshop/AppTest.java
图 B7-1 骨架生成成功：目录下出现 src/main/java/com/acme/bookshop/App.java 与 pom.xml（含一个测试类 AppTest）

B7.2 配置 pom.xml（加 ngdbc 依赖 + exec 插件）

骨架的 pom.xml 只有 JUnit 测试依赖。我们加上：① ngdbc 依赖（连 HANA 的驱动）；② exec-maven-plugin（直接运行 main，免打包）；③ 明确 maven.compiler.release=17。整体覆盖成下面这份：

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.acme.bookshop</groupId>
  <artifactId>bookshop-maven</artifactId>
  <version>1.0-SNAPSHOT</version>
  <packaging>jar</packaging>

  <name>bookshop-maven</name>

  <properties>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <maven.compiler.release>17</maven.compiler.release>
  </properties>

  <dependencies>
    <!-- SAP HANA JDBC 驱动（版本以 Maven Central 为准） -->
    <dependency>
      <groupId>com.sap.cloud.db.jdbc</groupId>
      <artifactId>ngdbc</artifactId>
      <version>2.28.8</version>
    </dependency>
  </dependencies>

  <build>
    <plugins>
      <!-- 用 exec 插件直接运行 main，无需打包 -->
      <plugin>
        <groupId>org.codehaus.mojo</groupId>
        <artifactId>exec-maven-plugin</artifactId>
        <version>3.2.0</version>
        <configuration>
          <mainClass>com.acme.bookshop.App</mainClass>
        </configuration>
      </plugin>
    </plugins>
  </build>
</project>

B7.3 替换 App.java

把骨架的 App.java 覆盖成我们的读库程序。这里用一个 COUNT 先取总数、再联表查询打印，逻辑与 B6 相同，只是交给 Maven 编译：

package com.acme.bookshop;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

/**
 * 模式二 · Maven 工程（archetype 骨架 + exec 插件）
 * JDBC 连接 HANA Cloud 的 BOOKSHOP 库，联表读取 Books 打印。
 */
public class App {

    // TODO: 换成你 HANA Cloud 实例的 SQL End Point 主机（B3 章「Copy SQL End Point」）
    static final String HOST = "xxxx.hana.trial-us10.hanacloud.ondemand.com";
    static final String URL =
        "jdbc:sap://" + HOST + ":443?encrypt=true&validateCertificate=true";
    static final String USER = "DBADMIN";
    static final String PASSWORD = "你的数据库口令";   // TODO: 替换为 DBADMIN 口令

    static final String COUNT_SQL = "SELECT COUNT(*) AS CNT FROM BOOKSHOP.BOOKS";

    static final String SQL =
        "SELECT b.ID, b.TITLE, a.NAME AS AUTHOR, g.NAME AS GENRE, " +
        "       b.STOCK, b.PRICE, b.CURRENCY " +
        "  FROM BOOKSHOP.BOOKS b " +
        "  JOIN BOOKSHOP.AUTHORS a ON a.ID = b.AUTHOR_ID " +
        "  JOIN BOOKSHOP.GENRES  g ON g.ID = b.GENRE_ID " +
        " ORDER BY b.ID";

    public static void main(String[] args) throws Exception {
        try (Connection conn = DriverManager.getConnection(URL, USER, PASSWORD)) {
            int total;
            try (PreparedStatement ps = conn.prepareStatement(COUNT_SQL);
                 ResultSet rs = ps.executeQuery()) {
                rs.next();
                total = rs.getInt("CNT");
            }
            System.out.println("共读取 " + total + " 本书（BOOKSHOP.BOOKS）");
            System.out.printf("%-2s  %-22s  %-18s  %-16s  %4s  %8s  %s%n",
                    "ID", "TITLE", "AUTHOR", "GENRE", "STOCK", "PRICE", "CURR");
            try (PreparedStatement ps = conn.prepareStatement(SQL);
                 ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    System.out.printf("%-2d  %-22s  %-18s  %-16s  %4d  %8.2f  %s%n",
                            rs.getInt("ID"), rs.getString("TITLE"), rs.getString("AUTHOR"),
                            rs.getString("GENRE"), rs.getInt("STOCK"),
                            rs.getDouble("PRICE"), rs.getString("CURRENCY"));
                }
            }
        }
    }
}

B7.4 编译并运行

mvn compile 编译并下载 ngdbc；exec:java 用 exec 插件直接跑 main。两步合并成一条命令：

mvn compile exec:java
BAS 终端 — mvn compile exec:java
$ mvn compile exec:java
[INFO] Scanning for projects...
[INFO] Downloaded ngdbc:2.28.8 (2.3 MB)
[INFO] BUILD SUCCESS
[INFO] --- exec-maven-plugin:3.2.0:java
共读取 10 本书（BOOKSHOP.BOOKS）
ID TITLE AUTHOR GENRE STOCK PRICE CURR
1 Wuthering Heights Emily Brontë Fiction 12 11.11 EUR
… （共 10 行）
图 B7-2 Maven 自动下载 ngdbc、编译、执行；输出与 B6 相同。首次运行会下载较多依赖，稍等片刻
💡 为什么用 mvn compile exec:java 而不是 mvn package archetype 骨架默认带一个会跑的 JUnit 测试类 AppTest，package 阶段会执行它（通常也会过，但多余）。直接 compile + exec:java 只编译并运行 main，最省事。想真正打包发布再走 mvn package。

B7.5 操作手顺

  1. 生成骨架

    在 projects/ 下执行 B7.1 的 mvn archetype:generate，进入生成的 bookshop-maven/。

  2. 覆盖 pom.xml

    把根 pom.xml 覆盖成 B7.2 的内容（加 ngdbc + exec 插件，编译目标 17）。

  3. 覆盖 App.java

    把 src/main/java/com/acme/bookshop/App.java 覆盖成 B7.3 的内容，替换 HOST / PASSWORD 占位符。

  4. 编译并运行

    执行 mvn compile exec:java，看到「共读取 10 本书」+ 10 行即成功（见图 B7-2）。

  5. 对照验证

    与 B4.5 的 SQL 结果、B6 的输出三方比对，数据一致即链路正确。

⚠️ 常见问题
  • archetype 卡在下载：首次会拉一堆插件。BAS 网络一般没问题；若慢，检查 ~/.m2/settings.xml 是否配了镜像。
  • 编译版本错误：报「release version 17 not supported」说明 BAS 默认 JDK 不是 17。先 java -version 确认；或改 <maven.compiler.release> 匹配你的 JDK。
  • ngdbc 版本找不到：版本号以 Maven Central 为准，2.28.8 只是示例，去 Central 看最新版本替换。
  • exec:java 报 NoClassDefFound：多为依赖未解析，先 mvn -q dependency:resolve 再运行。
