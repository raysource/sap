第 J2 章：环境准备

JDK 17 + Maven 3.8+ + cds-dk + IDE —— 搭起 CAP Java 的开发环境

CAP Java 基于 Spring Boot 与 Maven，环境比 Node 版多「一个 JDK、一个构建工具」。核心是四样：JDK 17（编译与运行）、Maven 3.8+（构建，且必须跑在 JDK 17 上）、@sap/cds-dk（脚手架，cds init --java 需要它）、任选一个 IDE。

JDK 17 LTS Maven 3.8+ @sap/cds-dk IntelliJ / Eclipse STS4 VS Code（轻量） SQLite（无需手动装）

J2.1 前置要求：JDK 17

CAP Java 要求 JDK 17 LTS（长期支持版，2026 年仍在维护期内；JDK 21 亦可）。这是硬性要求——cds-maven-plugin 与 CAP 运行时都需要 Java 17 的特性。安装方式按系统选：

  • macOS（推荐）：Homebrew 安装 brew install openjdk@17；或从 Adoptium（Eclipse Temurin） 下载安装包。
  • Windows：从 Adoptium 或 Oracle 下载 JDK 17 安装包，安装后把 JAVA_HOME 与 PATH 指到安装目录。
  • Linux（Ubuntu/Debian）：sudo apt install openjdk-17-jdk；Fedora/RHEL：sudo dnf install java-17-openjdk-devel。

Homebrew 装的 openjdk@17 是 keg-only（不自动进 PATH），需要手动设置 JAVA_HOME；这一步对后续 Maven 至关重要：

brew install openjdk@17

# openjdk@17 是 keg-only，需手动配置 JAVA_HOME（写入 ~/.zshrc 永久生效）
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export PATH="$JAVA_HOME/bin:$PATH"

装好后在新开的终端里验证版本：

终端 — 验证 JDK
$ java -version
openjdk version "17.0.11" 2024-04-16 LTS
OpenJDK Runtime Environment Homebrew (build 17.0.11+0)
OpenJDK 64-Bit Server VM Homebrew (build 17.0.11+0, mixed mode, sharing)
$ javac -version
javac 17.0.11
图 J2-1 java -version 输出 17 即满足 CAP Java 要求；javac -version 确认编译器与运行时一致

J2.2 构建工具：Maven 3.8+

CAP Java 用 Maven 管理依赖、编译、生成代码与启动。要求 Maven 3.8+，并且它必须运行在 JDK 17 之上（JAVA_HOME 指向 JDK 17，否则 cds-maven-plugin 会报「Java 版本太低」）。macOS 直接 Homebrew：

brew install maven

验证 mvn -version，重点看最后那行 Java version 是不是 17：

终端 — 验证 Maven
$ mvn -version
Apache Maven 3.9.6 (bc0240f3c744dd6b6ec2920b3cd08dcc9d4d3d47)
Maven home: /usr/local/Cellar/maven/3.9.6/libexec
Java version: 17.0.11, vendor: Homebrew, runtime: /usr/local/Cellar/openjdk@17/17.0.11/...
Default locale: en_US, platform encoding: UTF-8
OS name: "mac", version: "14.5", arch: "aarch64", family: "mac"
图 J2-2 mvn -version 里的 Java version: 17.0.11 说明 Maven 跑在 JDK 17 上——这是 CAP Java 构建的前提
💡 为什么 JAVA_HOME 这么关键 Maven 启动时读 JAVA_HOME 决定用它自己的 JVM 版本。如果指向 JDK 8 / 11，即使系统默认 java 是 17，Maven 仍会以旧版本运行，cds-maven-plugin 编译 CDS 时会直接失败。设置后务必重开终端再验证。

J2.3 脚手架：@sap/cds-dk

cds-dk 是 CAP 的命令行工具包，提供 cds init（建项目）、cds compile（编译模型）等命令。它是 Node.js 工具，用 npm 全局安装——若尚未安装 Node.js ≥ 18，先按 CAP 主路线环境准备 装好：

npm install -g @sap/cds-dk

注意：Java 路线不需要 Node.js 运行时（运行走 Spring Boot），Node.js 只用于跑 cds 命令行。安装后验证：

终端 — 安装并验证 cds-dk
$ npm install -g @sap/cds-dk
npm - added 183 packages in 9s
 
$ cds --version
@sap/cds    : 8.4.1
@sap/cds-dk : 8.2.1
 
$ cds init --help
Options: ... --java generate a Java project skeleton (Maven / Spring Boot)
图 J2-3 cds --version 确认脚手架可用；cds init --help 能看到 --java 选项

CAP 官方推荐 IntelliJ IDEA（Java 生态最顺手）；Eclipse + Spring Tools 4（STS4） 是经典选择；VS Code + Java Extension Pack 作为轻量选项也完全够用。三种 IDE 打开 CAP Java 项目的方式本质都是「把根 pom.xml 当 Maven 项目导入」：

J2.5 操作手顺

  1. 安装 JDK 17

    macOS brew install openjdk@17；Windows/Linux 用 Adoptium 安装包或包管理器。用 java -version 与 javac -version 验证（见图 J2-1）。

  2. 设置 JAVA_HOME 并验证

    把 JAVA_HOME 指向 JDK 17，写入 shell 配置文件（macOS：export JAVA_HOME=$(/usr/libexec/java_home -v 17)），重开终端确认生效。

  3. 安装 Maven 3.8+

    macOS brew install maven。用 mvn -version 确认 Java version: 17（见图 J2-2）。

  4. 全局安装 cds-dk

    先确认 Node.js ≥ 18（见 CAP 主路线环境准备），再 npm install -g @sap/cds-dk，用 cds --version 验证（见图 J2-3）。

  5. 安装 IDE 并导入项目

    任选 IntelliJ IDEA / Eclipse STS4 / VS Code。等 J3 章生成项目后，用「打开根 pom.xml」的方式导入（见图 J2-4）。

  6. 整体验证

    临时目录执行 cds init smoke --java 生成项目，再 cd smoke && mvn -q compile，看到 BUILD SUCCESS 即环境链路打通（J3 章详解每条命令）。

⚠️ 常见问题
  • JDK 版本不匹配：cds-maven-plugin 明确要求 Java 17+，用 JDK 8/11 会在 mvn 编译时报「不受支持的 class file / 版本错误」。装 17 LTS 即可。
  • JAVA_HOME 未设置：mvn -version 里 Java version 显示的是系统默认 JDK 而非 17，说明 JAVA_HOME 没指对或没在新终端里生效。
  • 国内 Maven 下载慢：在 ~/.m2/settings.xml 配置阿里云镜像 <mirror> 指向 https://maven.aliyun.com/repository/public，首次构建会快很多。
  • Eclipse 太旧：STS4 需 4.19+ 才支持 Java 17 与 CAP 插件；老版本直接装不上或导入报错，建议用 IntelliJ Community 或升级 STS4。

答案与解析（🟢 基础巩固（1–7））
题号答案解析
