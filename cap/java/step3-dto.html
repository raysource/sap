第 J5 章：手顺3 — DTO → 生成模型与服务

看看 CAP 帮你生成的 Books 类与服务接口，再亲手写唯一需要的业务代码——事件处理器

J3.1 里我们手写过一个 Book DTO，还抱怨过要配套 Controller / DAO / DDL。这一章看 CAP 在编译期替你生成的「等价但更强」的 Books 类与 CatalogService_ 服务接口，然后写一个事件处理器（Handler）完成「给高库存书加畅销标注」和「提交订单扣库存」两段业务逻辑。

CdsData CatalogService_ @After / @On PersistenceService CqnSelect / Update ServiceException

J5.1 回顾：J3.1 手写的 Book DTO

在 手顺1 J3.1 我们手写过 Book：一个字段 + getter/setter 的 JavaBean，还得另配 Repository/DAO、Controller、建表 DDL，字段一改三处同步改。这章看 CAP 的替代方案——模型写一次，DTO 对应的类与接口全部编译期生成。

J5.2 生成的模型类 Books

执行 mvn clean install 后，cds-maven-plugin 把 entity Books 编译成 Java 接口，落在 srv/target/generated-sources/cds/sap/capire/bookshop/Books.java。示意如下（字段与 CDS 完全一致，为便于阅读省略了部分 getter/setter）：

// sap/capire/bookshop/Books.java —— 由 schema.cds 的 entity Books 生成（示意）
package sap.capire.bookshop;

import java.math.BigDecimal;
import com.sap.cds.CdsData;

public interface Books extends CdsData {
    String ID = "ID";
    String TITLE = "title";
    String STOCK = "stock";
    String PRICE = "price";
    String AUTHOR = "author";

    Integer getId();
    Books setId(Integer id);
    String getTitle();
    Books setTitle(String title);
    Integer getStock();
    Books setStock(Integer stock);
    BigDecimal getPrice();
    Books setPrice(BigDecimal price);
    Authors getAuthor();           // 关联 → 类型化访问
    Books setAuthor(Authors author);
}

对照 J3.1 手写的 Book DTO，几处「升级」：

  • 字段类型由 CDS 推断：Decimal(9,2) → BigDecimal；Date 字段会映射成 LocalDate；Integer 主键 → Integer。
  • 关联变成类型化对象：getAuthor() 返回 Authors，导航属性类型安全，不用手写外键映射。
  • 多了列名常量：Books.STOCK、Books.PRICE 等，供查询/更新时引用（见 J5.4）。
  • 实现 CdsData：框架用它做 OData 序列化与 CDS 数据访问，这是手写 DTO 没有的「内功」。

J5.3 生成的服务接口 CatalogService_

由 srv/cat-service.cds 的 service CatalogService 生成，命名约定是「服务名 + 下划线」。它把服务名与 CDS 里声明的 action 变成常量，让业务代码用常量绑定事件而非字符串拼写：

// sap/capire/bookshop/CatalogService_.java —— 由 cat-service.cds 生成（示意）
package sap.capire.bookshop;

import com.sap.cds.services.cds.CdsService;

public interface CatalogService_ extends CdsService {
    String CDS_NAME = "CatalogService";               // 与 service 块同名
    String EVENT_SUBMIT_ORDER = "submitOrder";        // CDS 里声明的 action
}

用法两条：

  • 绑定服务：处理器类上用 @ServiceName(CatalogService_.CDS_NAME)，声明「我只处理 CatalogService 的事件」。
  • 绑定事件：方法上用 @On(event = CatalogService_.EVENT_SUBMIT_ORDER)，替代手写的事件名常量，拼错即编译报错。

J5.4 事件处理器：你唯一手写的业务代码

这是整条 Java 路线唯一要你写的业务代码。新建 com.acme.bookshop.handlers 包，写入 CatalogServiceHandler.java：

// srv/src/main/java/com/acme/bookshop/handlers/CatalogServiceHandler.java
package com.acme.bookshop.handlers;

import java.util.List;
import org.springframework.stereotype.Component;

import com.sap.capire.bookshop.Books;
import com.sap.capire.bookshop.CatalogService_;

import com.sap.cds.services.cds.CdsBeforeCreateContext;
import com.sap.cds.services.cds.CdsOnEventContext;
import com.sap.cds.services.cds.CdsService;
import com.sap.cds.services.handler.EventHandler;
import com.sap.cds.services.handler.annotations.After;
import com.sap.cds.services.handler.annotations.Before;
import com.sap.cds.services.handler.annotations.On;
import com.sap.cds.services.handler.annotations.ServiceName;
import com.sap.cds.ql.CqnSelect;
import com.sap.cds.ql.Select;
import com.sap.cds.ql.Update;
import com.sap.cds.services.ErrorStatuses;
import com.sap.cds.services.ServiceException;
import com.sap.cds.services.persistence.PersistenceService;

import io.vertx.core.json.JsonObject;

@Component
@ServiceName(CatalogService_.CDS_NAME)
public class CatalogServiceHandler implements EventHandler {

    private final PersistenceService db;

    public CatalogServiceHandler(PersistenceService db) {   // Spring 注入
        this.db = db;
    }

    @After(event = CdsService.EVENT_READ)
    public void markBestseller(List<Books> books) {
        books.forEach(b -> {
            if (b.getStock() != null && b.getStock() > 100) {
                b.setTitle(b.getTitle() + "（畅销）");
            }
        });
    }

    @Before(event = CdsService.EVENT_CREATE)
    public void validateNewBook(CdsBeforeCreateContext context) {
        JsonObject data = context.getData();
        Integer stock = data.getInteger("stock");
        if (stock != null && stock < 0) {
            throw new ServiceException(ErrorStatuses.BAD_REQUEST,
                "stock must not be negative, got: " + stock);
        }
    }

    @On(event = CatalogService_.EVENT_SUBMIT_ORDER)
    public void submitOrder(CdsOnEventContext context) {
        JsonObject data = context.getData();
        int bookId   = data.getInt("book");
        int quantity = data.getInt("quantity");

        CqnSelect sel = Select.from(Books.class).where(b -> b.ID().eq(bookId));
        Books book = db.run(sel).single(Books.class);

        if (book == null) {
            throw new ServiceException(ErrorStatuses.NOT_FOUND, "Book #" + bookId + " not found");
        }
        if (quantity > book.getStock()) {
            throw new ServiceException(ErrorStatuses.BAD_REQUEST,
                quantity + " exceeds stock for book #" + bookId);
        }
        db.run(Update.entity(Books.class)
            .data(Books.STOCK, book.getStock() - quantity)
            .where(b -> b.ID().eq(bookId)));
    }
}

逐块解释：

  • @Component + @ServiceName(CatalogService_.CDS_NAME)：把类注册为 Spring 组件，并声明它处理 CatalogService 的事件。@Component 保证它被 Spring Boot 组件扫描到（Application 在 com.acme.bookshop 包，能扫到 handlers 子包）。
  • 构造器注入 PersistenceService：Spring 自动注入持久化服务，后续用 db.run(...) 执行 CDS 查询与更新。
  • @After(event = CdsService.EVENT_READ)：读操作之后触发。List<Books> 是本次读出的数据行，遍历时给库存 > 100 的书标题加上「（畅销）」——只改返回给客户端的对象，不改库。
  • @Before(event = CdsService.EVENT_CREATE)：写操作（POST）之前触发，做参数校验。context.getData() 是待写入的载荷，这里拦截库存为负的新书并抛 400——校验失败时数据不会被写入。@Before 与 @After 构成前置校验 / 后置加工的一对，@On 是中间的核心处理。
  • @On(event = CatalogService_.EVENT_SUBMIT_ORDER)：处理 submitOrder action（@On 代表「接管」，覆盖默认行为）。context.getData() 返回 JsonObject，getInt("book") 取 action 参数。
  • Select.from(Books.class).where(b -> b.ID().eq(bookId))：用生成的模型类做类型化查询。b.ID() 是生成接口提供的方法引用，db.run(sel).single(Books.class) 返回第一行（无则 null）。
  • Update.entity(Books.class).data(Books.STOCK, ...)：类型化更新，用列名常量 Books.STOCK 指定字段，where 定位行。
  • ServiceException(ErrorStatuses.NOT_FOUND / BAD_REQUEST, ...)：抛异常会由框架自动转成OData 错误响应（4xx + JSON 错误体），J6 章能看到效果。
  • 事务：与 Node 版一致，CAP Java 把每个请求自动包裹在一个事务里——handler 正常返回 → 自动 commit；抛 ServiceException 或其他异常 → 自动 rollback。一个 @On 处理器里的多次 db.run（如先更新、后插入）要么全部生效，要么全部回滚，不需要手写事务边界。

J5.5 对照表：手写 DTO 全家桶 vs CAP Java 一个 Handler

关注点传统 Java（手写 DTO + Controller + DAO）CAP Java（一个 Handler）
字段/类型定义Book.java 手写字段 + getter/setter，与表同步维护schema.cds 写一行实体，Books 类编译期生成
表结构另写 CREATE TABLE，字段一改两边改启动按模型自动建表（J4 章）
接口暴露手写 Controller + 序列化 + OData 映射OData V4 自动生成，无需路由代码
CRUD 数据访问DAO 手写 SQL / ORM 映射框架默认 CRUD + 类型化 db.run(Select/Update)
业务逻辑散落在 Service/Controller 各层集中在 @After / @On 注解方法里
估算工作量DTO + Repository + Controller ≈ 150+ 行重复代码一个 CatalogServiceHandler ≈ 40 行业务逻辑

J5.7 操作手顺

  1. 构建以生成类

    项目根目录执行 mvn clean install，确认 target/generated-sources/cds/sap/capire/bookshop/ 下出现 Books.java、CatalogService_.java。

  2. 建 handlers 包

    在 srv/src/main/java/com/acme/bookshop/ 下新建 handlers 包（IDEA/Eclipse 里右键 → New Package）。

  3. 写处理器

    把 J5.4 的 CatalogServiceHandler.java 完整写入，保存后确认无编译错误（IDE 能识别生成的 Books / CatalogService_）。

  4. 重启应用

    在 srv/ 目录 mvn spring-boot:run（或根目录 mvn -pl srv spring-boot:run），等 Tomcat started on port 8080。

  5. 验证业务逻辑

    浏览器访问 http://localhost:8080/odata/v4/catalog/Books，看库存 > 100 的《The Raven》(333) 标题是否带「（畅销）」；再用 curl 调 submitOrder（见图 J5-2）。

图 J5-2 读 Books 时库存 333 的《The Raven》标题带「（畅销）」；调 submitOrder 后书 #1 库存从 12 降到 10——两段业务逻辑都生效
⚠️ 注意点
  • 生成的类在 target 下，勿改：Books.java 等是构建产物，改模型后重新 mvn clean 会覆盖你的修改。业务代码一律放 src/main/java。
  • Books.class 是接口：生成的模型是 interface（extends CdsData），Select.from(Books.class) 传的是它的 Class 对象，用法与实体类一致。
  • CqnSelect 类型：Select.from(...) 返回 CqnSelect，交给 db.run(sel) 执行；结果用 .single(Books.class) 映射为类型化对象。
  • 组件扫描：处理器类加 @Component 即可被 Spring 扫描。前提是它位于 @SpringBootApplication 启动类所在包（com.acme.bookshop）之下。
  • context.getData()：action 的入参在 JsonObject 里，data.getInt("book") 取 CDS 里声明的 book 参数。
