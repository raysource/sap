第 J4 章：手顺2 — 配置链接与建库建表

模型驱动建表：你只配置「连哪个数据库」，表结构、DDL、种子数据由框架自动完成

CAP Java 的「库与表」是模型驱动的——表结构由 db/schema.cds 定义，应用启动时框架按模型自动执行 DDL 建表，不需要手写任何 CREATE TABLE。你要做的只是：定义模型、告诉框架连哪个数据库、把种子数据 CSV 放对位置。

schema.cds application.yaml SQLite 自动 DDL sqlite-jdbc CSV 种子数据

J4.1 概念：库与表是「模型驱动」的

传统 Java 开发里建表要写 CREATE TABLE，还要让表字段与 Java 实体保持同步。CAP Java 把这一步完全自动化：

  • 实体 = 表：schema.cds 里每个 entity 启动时自动变成一张表，字段类型自动映射（String → VARCHAR、Decimal → DECIMAL、Date → DATE）。
  • 关联 = 外键：Association 自动变成外键列（author → author_ID）。
  • 你只配置数据源：在 application.yaml 里写一行 JDBC URL，告诉框架「连 SQLite 的这个文件」。建表语句由框架生成并执行。

J4.2 ① 复用 Bookshop 模型 db/schema.cds

沿用与 Node 版手顺2 完全一致的 Bookshop 模型——同一份 schema.cds，Node 版运行时解释、Java 版编译成类。完整写入 db/schema.cds：

// db/schema.cds —— 领域模型（数据层），Java 版与 Node 版完全一致
namespace sap.capire.bookshop;

entity Genres {
  key ID    : Integer;
      name  : String(64) @title : 'Genre';
      descr : String(512);
}

entity Authors {
  key ID          : Integer;
      name        : String(128) @title : 'Author';
      dateOfBirth : Date;
      placeOfBirth : String(128);
      books       : Association to many Books on books.author = $self;
}

entity Books {
  key ID     : Integer;
      title  : String(256) @title : 'Title';
      descr  : String(1024);
      author : Association to Authors;
      genre  : Association to Genres;
      stock  : Integer @title : 'Stock';
      price  : Decimal(9,2) @title : 'Price';
      currency : String(3);
}

要点：

  • namespace sap.capire.bookshop;：给所有实体加命名空间前缀，完整实体名是 sap.capire.bookshop.Books。它同时决定表名（见 J4.6 的下划线约定）与 CSV 文件名。
  • key ID : Integer;：主键。这里用自增 Integer，构建后对应 Java 的 Integer 类型。
  • Association to Authors / to Genres：对一关联，启动时变成 author_ID / genre_ID 外键列，OData 里可 $expand。
  • @title : 'Genre'：CDS 注解，提供 UI 友好的显示名，会体现在 OData $metadata 与 Fiori UI 上。

同时还要一个服务定义 srv/cat-service.cds（与 Node 版 4.2 同源，但去掉 @readonly，让 Books 可写，便于 J6 章练习 OData 增删改；并声明自定义 Action submitOrder，J5 章用它写业务逻辑）：

// srv/cat-service.cds —— 服务定义（服务层），Java 版
using { sap.capire.bookshop as my } from '../db/schema';

service CatalogService {
  entity Books   as projection on my.Books;
  entity Authors as projection on my.Authors;
  entity Genres  as projection on my.Genres;

  action submitOrder(book : Integer, quantity : Integer);   // 提交订单，扣减库存
}

种子数据：放对位置才会被导入

J4.3 ② 配置数据源 application.yaml

本地开发用 SQLite（文件型数据库，零配置）。编辑 srv/src/main/resources/application.yaml：

# srv/src/main/resources/application.yaml —— 本地开发（SQLite）
spring:
  datasource:
    url: jdbc:sqlite:./db.sqlite
    driver-class-name: org.sqlite.JDBC
server:
  port: 8080

逐行解释：

  • spring.datasource.url：JDBC 连接串。jdbc:sqlite: 是驱动前缀，./db.sqlite 是数据库文件路径（相对启动时的工作目录——在 srv/ 目录跑 mvn spring-boot:run 则文件在 srv/db.sqlite）。文件不存在时首次启动会自动创建。
  • driver-class-name：JDBC 驱动类 org.sqlite.JDBC，来自 sqlite-jdbc 依赖（见 J4.4）。
  • server.port：Spring Boot 监听端口，CAP Java 版默认 8080（Node 版是 4004）。

J4.4 ③ 添加 JDBC 驱动依赖

在 J3 章生成的 srv/pom.xml 示例里已经出现过 org.xerial:sqlite-jdbc——它的作用就是提供 SQLite 的 JDBC 驱动，没有它 application.yaml 里的 driver-class-name 就找不到类：

<!-- srv/pom.xml（节选） -->
<dependency>   <!-- SQLite 驱动：本地开发用 -->
  <groupId>org.xerial</groupId>
  <artifactId>sqlite-jdbc</artifactId>
</dependency>
💡 一句话对照：H2 vs SQLite 若想在自动化测试里用内存数据库 H2，只需把依赖换成 com.h2database:h2，并把 application.yaml 的 url 改成 jdbc:h2:mem:testdb——模型、代码、建表逻辑零改动。本培训本地开发统一用 SQLite。

J4.5 ④ 启动：自动建表 + 导入种子数据

一切就绪，构建并启动。启动瞬间 CAP 读取编译后的 CSN 模型，在 SQLite 里自动建表并导入 db/data 的 CSV：

mvn clean install        # 编译模型 → 生成 Java 类
cd srv

J4.6 ⑤ 查看生成的 DDL

想确认「模型到底变成了什么表」，用 cds compile 直接把 CDS 编译成 SQL（不启动应用也能看）：

cds compile db/schema.cds --to sql --dialect sqlite

输出的核心是 Books 表——注意「点号命名空间 → 下划线表名」的约定：sap.capire.bookshop.Books 变成 sap_capire_bookshop_Books，关联字段自动带上 _ID 后缀，最后还有外键约束：

-- cds compile db/schema.cds --to sql --dialect sqlite（节选）
CREATE TABLE sap_capire_bookshop_Books (
  ID INTEGER NOT NULL,
  title VARCHAR(256) NULL,
  descr VARCHAR(1024) NULL,
  author_ID INTEGER NULL,
  genre_ID INTEGER NULL,
  stock INTEGER NULL,
  price DECIMAL(9,2) NULL,
  currency VARCHAR(3) NULL,
  PRIMARY KEY(ID)
);

ALTER TABLE sap_capire_bookshop_Books
  ADD FOREIGN KEY(author_ID) REFERENCES sap_capire_bookshop_Authors(ID);
ALTER TABLE sap_capire_bookshop_Books
  ADD FOREIGN KEY(genre_ID) REFERENCES sap_capire_bookshop_Genres(ID);

对照模型，一眼能看懂映射：key ID : Integer → ID INTEGER NOT NULL ... PRIMARY KEY(ID)；title : String(256) → title VARCHAR(256)；price : Decimal(9,2) → price DECIMAL(9,2)；Association to Authors → 外键列 author_ID + FOREIGN KEY 约束。Genres / Authors 同理，前缀统一为 sap_capire_bookshop_。

J4.7 ⑥ 生产/云：换 HANA Cloud

部署到 HANA Cloud（生产级内存数据库）时，代码与模型零改动：CAP 在 Cloud Foundry 上自动读取服务绑定（Service Binding）注入 HANA 数据源，覆盖 application.yaml 里的本地 URL。DDL 仍由框架启动时执行，种子数据导入逻辑不变。本地「写完模型 → 启动建表」的心智，直接迁移到云端。

☁️ 想在云端手把手建 HANA Cloud 实例、用 HANA SQL 建同样的 Bookshop 库并灌入 10 本书、再用纯 JDBC 连库验证？见 B3 创建 HANA Cloud 实例 与 B4 HANA SQL 建表与数据。
💡 本地开发为什么要用 SQLite SQLite 是文件型数据库，无独立服务器、无端口、零安装，特别适合脚手架与快速验证；HANA 与之最大的差异只在连接方式与方言细节，模型层的体验完全一致。

J4.9 操作手顺

  1. 写 schema.cds

    把 J4.2 的模型完整写入 db/schema.cds，把 cat-service.cds 写入 srv/（含 submitOrder action）。

  2. 放种子数据 CSV

    在 db/data/ 下创建三个 CSV 文件（文件名、表头按 J4.2，完整数据见测试数据）。

  3. 写 application.yaml

    在 srv/src/main/resources/application.yaml 配 SQLite 数据源与端口 8080（见 J4.3）。

  4. 确认 sqlite-jdbc 依赖

    检查 srv/pom.xml 含 org.xerial:sqlite-jdbc；没有就补上（见 J4.4）。

  5. 构建

    项目根目录执行 mvn clean install，确认 BUILD SUCCESS，模型被编译成 Java 类与 CSN。

  6. 启动并验证

    cd srv && mvn spring-boot:run，观察建表/导入日志（见图 J4-2）；再用 sqlite3 db.sqlite 查表与数据（见图 J4-3）。

⚠️ 注意点
  • CSV 必须在 db/data/：放错目录（如直接放 db/）启动时不会导入，表是空的。
  • SQLite 是文件型：无服务器进程、无端口，别去找「SQLite 服务」。数据库就是一个 db.sqlite 文件。
  • 模型变化会重建表：schema.cds 改动后重新 mvn 编译再启动，框架会按新模型重建表——本地 SQLite 直接重建即可；生产 HANA 需走部署迁移，不要手工 DROP。
  • 生产勿用 SQLite：SQLite 单机单写、并发弱，只用于本地开发；生产用 HANA Cloud（见 J4.7）。
