第 J3 章：手顺1 — 建立 Java 项目

从「一个简单的 Java DTO」到「一个可运行的 CAP Java 项目」

这一章回答「Java 项目从哪来」。我们先写一个最普通的 Java DTO（数据传输对象），看清手写模式的痛点；然后 cds init --java 生成基于 Maven 的 Spring Boot 项目，由框架把 DTO 该干的活全部自动完成。

DTO cds init --java Maven 多模块 Spring Boot cds-maven-plugin

J3.1 起点：一个简单的 Java DTO

在传统 Java Web 开发里，你通常先写一个 DTO 来对应一张表/一个接口的字段。比如我们的 Book：

package com.acme.bookshop.model;

import java.math.BigDecimal;

/** 图书数据传输对象：对应 Books 表 */
public class Book {

    private Integer  id;
    private String   title;
    private String   descr;
    private Integer  stock;
    private BigDecimal price;
    private String   currency;

    public Integer getId()          { return id; }
    public void    setId(Integer v) { this.id = v; }
    public String  getTitle()       { return title; }
    public void    setTitle(String v){ this.title = v; }
    // …… 其余字段的 getter / setter 略（手写重复劳动）
}

有了 DTO 之后，传统方案还缺一大串配套：

  • 一个 Repository / DAO 写增删改查 SQL；
  • 一个 Controller 暴露 REST/OData 接口、做参数与序列化；
  • 一张 数据库表 的 DDL，还要和 DTO 字段保持同步；
  • DTO ↔ 实体 ↔ 表的三套映射代码。
⚠️ 手写模式的痛点 字段一多、实体一改，三处代码要同步改，极易漏改。CAP Java 的思路完全不同：模型（CDS）写一次，DTO 对应的类、表结构、OData 接口全部由框架生成，你只写业务规则。

J3.2 CAP 的做法：模型一次，类自动生成

对比关系一目了然——你不再手写 Book 这个 DTO，而是写一行 CDS 实体，构建时自动得到「等价但更强」的 Books 类（含类型映射、关联、CdsData 接口、服务事件）：

关注点传统 Java（手写 DTO）CAP Java
结构定义Book.java 手写字段 + getter/setterschema.cds 写一行 entity Books { ... }
数据库表另写 CREATE TABLE 并保持同步启动时按模型自动建表
接口另写 Controller / 序列化 / OData 映射OData V4 自动生成
CRUDRepository + SQL 手写框架默认 CRUD，覆盖前先可用
你要写的以上全部仅业务逻辑（事件处理器）

J3.3 cds init --java：生成项目骨架

打开终端，进入一个空目录，执行（注意与 Node 版只差一个 --java 参数）：

J3.4 项目结构：Maven 多模块

Java 版是典型的 Maven 多模块工程——根 pom.xml 聚合一个 srv 子模块，所有源码都放在 srv 里：

bookshop — Java 项目结构
▾📁 bookshop/
📄 pom.xml ← 父工程：版本、模块、依赖管理
📄 package.json ← cds 工具（init/build）用
▾📁 db/ ← 数据模型（与 Node 版共用）
📄 schema.cds
▾📁 srv/ ← Spring Boot 应用模块
📄 pom.xml
▾📁 src/main/java/com/acme/bookshop/
📄 Application.java ← Spring Boot 启动类
▾📁 src/main/resources/
📄 application.yaml ← 数据源/配置（手顺2 重点）

生成的启动类 Application.java

package com.acme.bookshop;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}

J3.5 关键构建配置：pom.xml

父 pom.xml 继承 CAP 官方 cds-parent（自动带来依赖版本管理与 cds-maven-plugin），聚合 srv 模块：

<!-- 根 pom.xml（节选） -->
<project>
  <parent>
    <groupId>com.sap.cds</groupId>
    <artifactId>cds-parent</artifactId>   <!-- CAP Java 依赖/插件管理 -->
    <version>2.7.0</version>
  </parent>
  <groupId>com.acme</groupId>
  <artifactId>bookshop</artifactId>
  <version>1.0.0-SNAPSHOT</version>
  <packaging>pom</packaging>
  <modules>
    <module>srv</module>                    <!-- 唯一的应用模块 -->
  </modules>
</project>

srv/pom.xml 引入 CAP 的 Spring Boot 启动器；cds-maven-plugin 在编译期把 CDS 编译成 Java（就是 J1 章说的「模型到代码」）：

<!-- srv/pom.xml（节选） -->
<project>
  <parent>
    <groupId>com.acme</groupId>
    <artifactId>bookshop</artifactId>
    <version>1.0.0-SNAPSHOT</version>
  </parent>
  <artifactId>srv</artifactId>
  <packaging>jar</packaging>
  <dependencies>
    <dependency>
      <groupId>com.sap.cds</groupId>
      <artifactId>cds-starter-spring-boot-starter</artifactId>
    </dependency>
    <dependency>   <!-- 本地开发用 SQLite（手顺2 详解） -->
      <groupId>org.xerial</groupId>
      <artifactId>sqlite-jdbc</artifactId>
    </dependency>
  </dependencies>
  <build>
    <plugins>
      <plugin>
        <groupId>com.sap.cds</groupId>
        <artifactId>cds-maven-plugin</artifactId>  <!-- CDS → Java 编译 -->
        <executions>
          <execution><goals><goal>clean</goal></goals></execution>
          <execution><goals><goal>generate</goal></goals></execution>
        </executions>
      </plugin>
    </plugins>
  </build>
</project>

图 J3-3 首次构建：cds-maven-plugin 把 CDS 编译成 Java，之后 Books.java 等即可被业务代码 import
💡 构建生成在 target 下，别手改 生成的 Java 在 srv/target/generated-sources/cds，属于构建产物。不要手改——改模型后重新 mvn 即可。你的业务代码（处理器）放在 src/main/java 下 import 它们（下一章）。

J3.7 操作手顺

  1. 确认工具就绪

    终端执行 java -version（JDK 17+）与 mvn -version（Maven 3.8+）；未安装见 环境准备。

  2. 生成项目

    空目录下执行 cds init bookshop --java，然后 cd bookshop。

  3. 对照 DTO 心智

    打开 db/schema.cds（目前为空模板）。回想 J3.1 手写的 Book DTO——接下来这一步就是「把 DTO 的字段声明交给 CDS」，见手顺2。

  4. 首次构建

    根目录执行 mvn clean install，确认 BUILD SUCCESS，target/generated-sources/cds 下出现模型类。

  5. 验证工程可运行

    （可选）在 srv 目录执行 mvn spring-boot:run，浏览器访问 http://localhost:8080，能返回 Spring Boot 默认页即工程链路 OK。

✅ 本章成果 一个基于 Maven + Spring Boot 的 CAP Java 项目骨架，构建成功，模型→代码的「生成通道」已打通。接下来手顺2 配置数据库连接、建立表；手顺3 亲手写业务代码。
💡 常见问题
  • 首次构建慢：在下载依赖，属正常；国内可配 Maven 镜像（阿里云 mirrors.aliyun.com）。
  • 找不到 cds 命令：说明未装 @sap/cds-dk，见环境准备 J2。
  • 端口 8080 被占：在 application.yaml 改 server.port（手顺2 会写到这个文件）。
  • 不要用 cds watch：它是 Node 版的启动方式；Java 版用 mvn spring-boot:run。
