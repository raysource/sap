第 J6 章：手顺4 — 运行与测试

spring-boot:run 启动 → OData 服务文档 → curl 读/建/删/调 Action → 对比 Node 版

模型、数据源、处理器都齐了，这一章把它跑起来：启动应用、打开 OData 服务文档、用 curl（或 Postman）完成对 Books 的读、建、删与调用 submitOrder Action，最后与 Node 版对比体验差异。

spring-boot:run OData V4 curl $expand / $filter Postman 端口 8080

J6.1 启动应用

在 srv/ 目录执行 mvn spring-boot:run（或项目根目录 mvn -pl srv spring-boot:run）。启动日志里能看到 CAP 连接数据库、挂载 OData 服务、最后由 Spring Boot 监听端口：

J6.3 OData 测试：curl 读 / 建 / 删 / 调 Action

用 curl 直接打 OData 接口。先看读取——注意 $top / $filter / $expand 前要写反斜杠转义 \$，否则 shell 会把它当变量：

# 读：Books 集合（JSON 数组）
curl http://localhost:8080/odata/v4/catalog/Books

# 读：只取前 3 条
curl "http://localhost:8080/odata/v4/catalog/Books?\$top=3"

# 读：价格 < 30 的书（%20 是 URL 编码的空格，等价于 price lt 30）
curl "http://localhost:8080/odata/v4/catalog/Books?\$filter=price%20lt%2030"

# 读：同时带出作者信息（导航属性展开）
curl "http://localhost:8080/odata/v4/catalog/Books?\$expand=author"

写入——由于 J4 章去掉了 @readonly，Books 支持增删。POST 创建返回 201 Created，DELETE 返回 204 No Content：

# 建：新建一本书（ID 是主键，由我们指定）→ 201
curl -X POST "http://localhost:8080/odata/v4/catalog/Books" \
     -H "Content-Type: application/json" \
     -d '{"ID":101,"title":"Test Book","author_ID":101,"genre_ID":201,"stock":5,"price":9.99,"currency":"EUR"}'

# 删：删除刚才那本书 → 204（-i 让 curl 显示响应状态行）
curl -i -X DELETE "http://localhost:8080/odata/v4/catalog/Books(101)"

调 Action——submitOrder 声明在服务上（见 J4.2 的 cat-service.cds），入参 book / quantity 放请求体，处理器 J5.4 负责扣库存：

curl -X POST "http://localhost:8080/odata/v4/catalog/submitOrder" \
     -H "Content-Type: application/json" \
     -d '{"book":1,"quantity":2}'

J6.4 与 Node 版对比

同一个 Bookshop 模型，两条路线的开发体验差异集中体现在「启动与热重载」：

维度Node.js 版Java 版
启动命令cds watchmvn spring-boot:run
端口40048080
改模型生效热重载：保存 CDS 即自动重载需重新 mvn 编译再重启应用
日志[cds] - server listening on http://localhost:4004[cds] - oData: serving ... + Tomcat started on port 8080
热重载体验秒级、无需人工介入，适合快速迭代每次重启数秒~数十秒；可配 spring-boot-devtools 改善 Java 代码热重载
本地数据库内置 SQLite，零配置SQLite / H2，靠 application.yaml 配 JDBC

J6.5 常见问题

⚠️ 排查清单
  • 端口 8080 被占：报 Port 8080 was already in use。改 application.yaml 的 server.port（如 8081）后重启。
  • 改 schema 后行为没变：Java 版是编译期生成类，改了 schema.cds 必须先 mvn clean（或 mvn clean install）重新生成，再重启——没有 Node 版的热重载。
  • CSV 没导进来：看启动日志里 data imported from db/data 那几行；若没有，确认 CSV 在 db/data/、文件名/表头与 J4.2 一致。
  • 前端跨域：本地开发一般放开 CORS（CAP 默认允许）；联调 Fiori 时可显式配置 @CrossOrigin 或网关。
  • cds run / cds watch 不适用于 Java：那是 Node 版的启动方式；Java 版统一用 mvn spring-boot:run。

J6.6 关于 Fiori Elements（一句话）

Java 版同样可以加 Fiori Elements：在 CDS 里加 UI 注解（annotate）并用 Fiori 工具生成前端，OData 端点不变（仍是 /odata/v4/catalog）。本培训聚焦后端运行时，前端部分不展开。

J6.7 操作手顺

  1. 启动应用

    在 srv/ 目录 mvn spring-boot:run，确认 Tomcat started on port 8080（见图 J6-1）。

  2. 打开服务文档

    浏览器访问 http://localhost:8080/odata/v4/catalog，确认三个实体集合；再访问 $metadata 看字段定义（见图 J6-2）。

  3. curl 读取

    依次执行 $top=3、$filter=price%20lt%2030、$expand=author，观察返回差异。

  4. curl 建 / 删

    POST 创建 ID=101 的书（期望 201），再 DELETE（期望 204），见 J6.3。

  5. 调 Action 并核对库存

    POST /odata/v4/catalog/submitOrder（服务级未绑定 Action，action 名直接接在服务根后），body {"book":1,"quantity":2}；随后 sqlite3 srv/db.sqlite "SELECT stock FROM sap_capire_bookshop_Books WHERE ID=1;" 应看到 12 → 10。

  6. 验证超卖被拒

    对库存为 0 的《Eleonora》（ID=4）下单 1 本，应返回 400 错误 JSON（见下）。

J6.8 验证：下单扣库存 & 超卖返回 400

下单成功后库存减少；当数量超过库存时，J5.4 的 ServiceException(BAD_REQUEST, ...) 被框架转成标准 OData 错误响应：

终端 — 下单与超卖
$ curl -X POST http://localhost:8080/odata/v4/catalog/submitOrder \
     -H "Content-Type: application/json" -d '{"book":1,"quantity":2}'
{}
$ sqlite3 srv/db.sqlite "SELECT ID, stock FROM sap_capire_bookshop_Books WHERE ID=1;"
1|10
 
$ curl -i -X POST http://localhost:8080/odata/v4/catalog/submitOrder \
     -H "Content-Type: application/json" -d '{"book":4,"quantity":1}'
HTTP/1.1 400
Content-Type: application/json;charset=UTF-8
{ "error": { "code": "400", "message": "1 exceeds stock for book #4" } }
图 J6-4 书 #1 库存从 12 降到 10；对库存 0 的书 #4 下单 1 本，返回 400 + 标准 OData 错误 JSON——业务规则与异常映射都按预期工作
✅ 本路线总结 从 J1 看差异、J2 配环境、J3 建项目、J4 配库建表、J5 写处理器，到 J6 运行测试——你已走完一条完整的 CAP Java 开发链路：模型写一次，建表、DTO、OData 接口全部自动，业务逻辑集中在一个 Handler 里。这趟「手写 DTO 全家桶 vs 一个 Handler」的对比，正是 CAP Java 的核心价值。
