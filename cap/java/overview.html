第 J1 章：CAP for Java 概述

Java 运行时 · Spring Boot · 「模型到代码」的编译期生成

CAP 支持 Node.js 与 Java 两种运行时，模型（CDS）与 OData 语义完全一致。Java 版基于 Spring Boot，在编译期把 CDS 模型生成成强类型 Java 类与服务接口——适合团队已有 Java/Spring 技术栈、需要强类型与成熟企业生态的场景。

Java 17+ Spring Boot Maven SQLite / H2 HANA Cloud

J1.1 Java 版 vs Node.js 版

两条路线共用同一份 schema.cds 模型，业务对象与 OData 行为一致，差别在运行时与开发方式：

维度Node.js 版Java 版
编程语言JavaScript / TypeScriptJava 17+
底层运行时自研 Node 服务器（Express 家族）Spring Boot（CAP Java 深度集成）
构建工具npm / npxMaven（或 Gradle）
项目生成cds init bookshopcds init bookshop --java
模型如何生效运行时解释 CSN编译期由 cds-maven-plugin 生成 Java 类，强类型
业务逻辑srv/*.js 事件 handlerJava 事件处理器（@ServiceName / @Before / @After / @On）
本地启动cds watch（自动重载，端口 4004）mvn spring-boot:run（端口 8080）
本地数据库SQLiteSQLite / H2（测试常用）
适合团队全栈 / 前端出身、求快Java / Spring 技术栈、强类型、企业集成

J1.3 编译期生成了什么

执行 mvn clean install 时，cds-maven-plugin 把 CDS 编译到 srv/target/generated-sources/cds，产出三类强类型 Java 源码：

bookshop/srv/target/generated-sources/cds — 生成的源码
▾📁 generated-sources/cds/
▾📁 sap/capire/bookshop/
📄 Genres.java — 模型类（implements CdsData）
📄 Authors.java — 模型类
📄 Books.java — 模型类（含关联字段）
📄 CatalogService.java — 服务接口（CdsService）
📄 CatalogService_.java — 规范服务类（CDS_NAME / EVENT_* 常量）
图 J1-1 编译期生成的 Java 产物：模型类 + 服务接口，可被你的业务代码直接 import
  • 模型类（如 Books）：一个 JavaBean，字段类型映射 CDS 类型（Integer、String、BigDecimal、LocalDate…），实现 com.sap.cds.CdsData，带 getter/setter——这就是我们手写「DTO」时想要的类，框架替你生成了。
  • 服务接口（CatalogService 与规范版 CatalogService_）：声明了该服务的 CDS_NAME（如 CatalogService）与可注册的事件（如 EVENT_SUBMIT_ORDER）。
  • 事件处理器骨架：CDS 里声明的 action 会生成对应事件常量，业务类用注解绑定。

J1.4 什么时候选 Java

✅ 推荐 Java

  • 团队已有 Java / Spring Boot 技术栈
  • 需要强类型、编译期就发现模型/逻辑错误
  • 要复用企业 Java 生态（Spring、JPA 经验、监控、安全框架）
  • 大规模服务，依赖成熟的线程/连接池管理

⚡ 推荐 Node

  • 团队偏前端 / 全栈，JavaScript 熟练
  • 快速原型、cds watch 秒级热重载体验
  • 轻量服务、启动快、依赖少
  • 模型频繁改动，不希望每次编译
