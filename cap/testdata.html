第 7 章：测试数据

可直接复制的 Bookshop CSV 种子数据与完整测试场景

本章给出第 4 章用到的完整 CSV 种子数据（分类 5 条、作者 4 位、图书 10 本、订单 2 条），以及覆盖 OData 查询、增删改、下单 Action 的测试场景清单。所有文件直接放进 db/data/，cds watch 启动即自动导入。

Genres ×5 Authors ×4 Books ×10 Orders ×2 curl 测试场景

加载数据操作手顺

  1. 创建 db/data/ 目录

    在项目根目录下确认 db/data/ 存在（不存在则创建）。

  2. 复制 CSV 文件

    把 7.2–7.5 的四个 CSV 按文件名放入 db/data/，保存为 UTF-8（无 BOM）。

  3. 启动并验证条数

    执行 cds watch，用 curl "...?\$count=true" 核对 Genres=5、Authors=4、Books=10（见图 7-1）。

  4. 执行测试场景

    对照 7.6 的场景清单逐一用 curl 验证，确认每个操作的预期结果。

7.6 测试场景清单

以下场景覆盖第 6 章的全部能力。表格中的命令均可直接复制到终端执行。

场景命令或操作预期结果
查全部图书curl http://localhost:4004/odata/v4/catalog/Books返回 JSON 数组，含全部 10 本（@odata.count 需要加 ?$count=true）
过滤低价书curl "http://localhost:4004/odata/v4/catalog/Books?\$filter=price%20lt%2030"只返回价格 < 30 的书（书 1/2/3/4/5/6/9）
展开作者关联curl "http://localhost:4004/odata/v4/catalog/Books?\$expand=author"每本书带 author 内嵌对象（含 name、dateOfBirth）
创建新书curl -X POST http://localhost:4004/odata/v4/catalog/Books -H "Content-Type: application/json" -d '{"ID":101,"title":"CAP in Action","author_ID":104,"genre_ID":201,"stock":5,"price":19.99,"currency":"EUR"}'返回 201 Created 与新书实体，GET Books(101) 可查到
修改价格curl -X PATCH http://localhost:4004/odata/v4/catalog/Books(101) -H "Content-Type: application/json" -d '{"price":25.50}'返回 200 OK，价格更新为 25.50
删除图书curl -X DELETE http://localhost:4004/odata/v4/catalog/Books(101)返回 204 No Content，再次读取返回 404
下单（库存充足）curl -X POST http://localhost:4004/odata/v4/catalog/submitOrder -H "Content-Type: application/json" -d '{"book":1,"quantity":5}'返回 {"updated":5}，随后查询书 1 库存由 12 减为 7
下单（库存不足）curl -X POST http://localhost:4004/odata/v4/catalog/submitOrder -H "Content-Type: application/json" -d '{"book":4,"quantity":1}'返回 400，消息 1 exceeds stock for book #4（书 4 库存为 0）
删除不存在的 IDcurl -X DELETE http://localhost:4004/odata/v4/catalog/Books(99999)返回 404，消息提示资源未找到

完整命令串（可直接复制）：

# 读取与查询
curl http://localhost:4004/odata/v4/catalog/Books
curl "http://localhost:4004/odata/v4/catalog/Books?\$filter=price%20lt%2030"
curl "http://localhost:4004/odata/v4/catalog/Books?\$expand=author"

# 创建 → 修改 → 删除（以 ID 101 为例）
curl -X POST http://localhost:4004/odata/v4/catalog/Books \
  -H "Content-Type: application/json" \
  -d '{"ID":101,"title":"CAP in Action","descr":"新书","author_ID":104,"genre_ID":201,"stock":5,"price":19.99,"currency":"EUR"}'
curl -X PATCH http://localhost:4004/odata/v4/catalog/Books(101) \
  -H "Content-Type: application/json" \
  -d '{"price":25.50}'
curl -X DELETE http://localhost:4004/odata/v4/catalog/Books(101)

# 下单 Action
curl -X POST http://localhost:4004/odata/v4/catalog/submitOrder \
  -H "Content-Type: application/json" \
  -d '{"book":1,"quantity":5}'        # 库存充足 → {"updated":5}
curl -X POST http://localhost:4004/odata/v4/catalog/submitOrder \
  -H "Content-Type: application/json" \
  -d '{"book":4,"quantity":1}'        # 库存不足 → 400

# 删除不存在 ID → 404
curl -X DELETE http://localhost:4004/odata/v4/catalog/Books(99999)

7.7 数据设计小贴士

💡 种子数据设计原则
  • 覆盖边界：测试数据刻意包含边界值——库存 0（触发下单失败）、库存 100+（触发「-- 畅销」）、价格 < 30 与 ≥ 30（验证 $filter）。
  • 关联完整：每本 Books 的 author_ID / genre_ID 都必须指向 Authors / Genres 里存在的 ID，否则外键解析失败、启动报错。
  • 区分测试与生产：这些 CSV 是本地演示数据；接入真实系统时应改为从 S/4HANA 或源系统抽取。
  • 重置数据：反复测试把库存改乱后，删除本地 bookshop.db（SQLite 文件）再 cds watch，数据会重新从 CSV 导入。
