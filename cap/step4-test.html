第 6 章：手顺4 —— 启动、测试与 Fiori

cds watch 启动 → OData CRUD 测试 → Fiori Elements 预览

前几章攒下的模型、服务、处理器，本章全部串起来：启动服务器，用 curl / POSTMAN 做一轮完整的 OData 增删改查与下单测试，最后用 Fiori Elements 把 Books 渲染成真实的 List Report 页面。

cds watch OData V4 curl Fiori Elements POSTMAN

6.2.1 curl 命令行测试

在终端用 curl 执行完整的 CRUD 与查询操作：

# ① 读取全部图书
curl http://localhost:4004/odata/v4/catalog/Books

# ② 查看服务的元数据（暴露所有实体、字段、注解）
curl http://localhost:4004/odata/v4/catalog/$metadata

# ③ 查询：价格低于 30（注意空格需 URL 编码为 %20）
curl "http://localhost:4004/odata/v4/catalog/Books?\$filter=price%20lt%2030"

# ④ 查询：只看前 3 条
curl "http://localhost:4004/odata/v4/catalog/Books?\$top=3"

# ⑤ 查询：展开关联的作者对象
curl "http://localhost:4004/odata/v4/catalog/Books?\$expand=author"

# ⑥ 创建新书（POST 新增，返回 201）
curl -X POST http://localhost:4004/odata/v4/catalog/Books \
  -H "Content-Type: application/json" \
  -d '{"ID":101,"title":"CAP in Action","descr":"新书","author_ID":104,"genre_ID":201,"stock":5,"price":19.99,"currency":"EUR"}'

# ⑦ 修改价格（PATCH 局部更新，返回 200）
curl -X PATCH http://localhost:4004/odata/v4/catalog/Books(101) \
  -H "Content-Type: application/json" \
  -d '{"price":25.50}'

# ⑧ 删除图书（DELETE 返回 204）
curl -X DELETE http://localhost:4004/odata/v4/catalog/Books(101)

6.3 步骤3：Fiori Elements 预览

数据接口测试通过后，用 Fiori Elements List Report 把 Books 渲染成可搜索、可筛选、可创建的业务页面。有两种搭建方式：

  • 手动方式（本培训采用）：在 app/books/ 下创建 annotate.cds（写 @UI 注解）+ manifest.json（应用配置）+ 空的 index.html。
  • 脚手架方式：用 cds add fiori 或 @sap/cds-fiori 包一键生成上述文件，再按需微调。

annotate.cds —— 用注解声明 UI

在 app/books/annotate.cds 中用 annotate 给服务投影追加 @UI 注解（不改原始模型），声明 List Report 的标题、表格列：

// app/books/annotate.cds —— 为 CatalogService.Books 声明 UI 注解
using CatalogService as service from '../srv/cat-service';

annotate service.Books with @(
  UI : {
    HeaderInfo : {
      TypeName : 'Book', TypeNamePlural : 'Books', Title : { Value : 'title' },
      Description : { Value : 'descr' }
    },
    LineItem : [
      { Value : 'title', Label : '书名' },
      { Value : 'price', Label : '价格' },
      { Value : 'stock', Label : '库存' },
      { Value : 'author.name', Label : '作者' }
    ]
  },
  Common.SemanticKey : ['ID']
);
  • UI.HeaderInfo：列表页与对象页的标题区配置（单数/复数名、主标题字段、描述字段）。
  • UI.LineItem：表格列定义，Value 可以是嵌套关联路径（如 author.name 直接显示作者姓名）。
  • Common.SemanticKey：声明业务语义键，用于跳转与去重。
  • annotate ... with：注解只叠加在服务投影上，db/schema.cds 保持纯净——这是 CAP 的推荐分层。
💡 注解文件的相对路径 annotate.cds 放在 app/books/ 下时，using ... from 指向服务的路径应为 ../../srv/cat-service；若放在 app/ 根目录则为 ../srv/cat-service。上面示例按 app/ 根目录路径书写，实际放置时按你的目录层级调整。

manifest.json —— 应用与数据源配置

创建 app/books/manifest.json，声明应用 ID、指向 CatalogService 的数据源与路由：

{
  "sap.app": {
    "id": "cap.bookshop.books",
    "type": "application",
    "dataSources": {
      "mainService": {
        "uri": "/odata/v4/catalog/",
        "type": "OData",
        "settings": { "odataVersion": "4.0" }
      }
    }
  },
  "sap.ui5": {
    "dependencies": {
      "libs": { "sap.m": {} }
    }
  },
  "routing": {
    "config": { "routerClass": "sap.m.routing.Router" },
    "routes": [
      { "pattern": "", "name": "BooksList", "target": "BooksList" }
    ],
    "targets": {
      "BooksList": {
        "type": "Component",
        "id": "BooksList",
        "name": "sap.fe.templates.ListReport",
        "options": { "settings": { "entitySet": "Books" } }
      }
    }
  }
}

保存后 cds watch 会自动拾取 app/ 下的应用。浏览器访问 http://localhost:4004/app/books/index.html（index.html 可以是几乎空白的引导页），即可看到渲染好的 List Report：

6.4 步骤4：错误排查与调试

症状原因 / 排查
启动报 EADDRINUSE端口 4004 被占用。换端口：cds watch --port 4005，或找出占用进程 lsof -i :4004。
启动报 CDS 语法错误（红字 + 文件名:行号）*.cds 语法错误。检查 entity 块大括号是否闭合、字段类型是否合法，按报错行列修正。
启动报 CSV 导入错误 invalid columnCSV 表头与实体字段不匹配（拼写/顺序/缺失 _ID 外键列）。对照第 7 章测试数据核对。
请求返回 404实体集合不存在或路径拼错。先访问 http://localhost:4004 服务索引页确认真实路径。
请求返回 400 / 500 且终端有堆栈handler 抛异常或 req.reject 被触发。看 cds watch 终端堆栈定位到 cat-service.js 的行。

需要断点调试时，用 Node 的调试模式启动：cds watch --inspect（等价 node --inspect），然后在 VS Code 的「运行与调试」里附加 localhost:9229 打断点。

6.5 操作手顺

  1. 启动服务器

    执行 cds watch，确认日志列出 CatalogService 与 http://localhost:4004（见图 6-1）。

  2. OData 测试

    用 curl / POSTMAN 依次执行读取、查询（$filter / $top / $expand）、创建、修改、删除与下单 Action（见6.2）。

  3. Fiori Elements 预览

    在 app/books/ 下创建 annotate.cds + manifest.json，访问 http://localhost:4004/app/books/index.html 查看 List Report（见6.3）。

  4. 排查与调试

    对照错误排查表（见6.4）定位端口占用、语法错误、CSV 不匹配等问题，必要时用 cds watch --inspect 断点调试。

⚠️ Fiori 预览与注解注意事项
  • 注解用 annotate 而非改原始模型：UI 注解写进 app/*/annotate.cds，保持 db/schema.cds 纯净，便于复用与升级。
  • 预览地址：Fiori 应用通过 http://localhost:4004/app/books/index.html 访问；没有 Fiori 项目文件时 CAP 也能用 cds serve --with-mocks 提供纯 OData 预览。
  • CORS：本地开发时 CAP 默认开放跨域（CORS），前端从其它端口发起请求不会报跨域错误。
  • 改 manifest / annotate 后：刷新浏览器即可看到新注解生效（cds watch 会重载 app/ 下文件）。
