第 4 章：手顺2 —— 数据模型与服务

db/schema.cds + srv/cat-service.cds + CSV 种子数据

本章为 Bookshop 定义领域模型（作者、分类、图书三个实体）、一个OData 服务（CatalogService）以及种子数据。写完保存，CAP 自动在 SQLite 里建表并载入 CSV 数据——这就是「模型驱动」的核心体验。

CDS Entity Association Projection CSV 种子数据

4.1 定义领域模型 db/schema.cds

在 db/schema.cds 中声明三个实体。整个文件如下，可直接复制：

// db/schema.cds —— 领域模型（数据层）
namespace sap.capire.bookshop;

using { cuid } from '@sap/cds/common';

entity Genres {
  key ID    : Integer;
      name  : String(64) @title : 'Genre';
      descr : String(512);
}

entity Authors {
  key ID          : Integer;
      name        : String(128) @title : 'Author';
      dateOfBirth : Date;
      placeOfBirth : String(128);
      books       : Association to many Books on books.author = $self;
}

entity Books {
  key ID     : Integer;
      title  : String(256) @title : 'Title';
      descr  : String(1024);
      author : Association to Authors;
      genre  : Association to Genres;
      stock  : Integer @title : 'Stock';
      price  : Decimal(9,2) @title : 'Price';
      currency : String(3);
}

逐行解释几个关键概念：

  • namespace sap.capire.bookshop;：给所有实体加命名空间前缀，生成的完整实体名为 sap.capire.bookshop.Books。命名空间也用于 CSV 文件命名（见 4.3）。
  • key ID : Integer;：key 声明主键。这里用自增 Integer 主键；后面第 5 章会用 cuid 生成 UUID 主键作为对照。
  • @title : 'Genre'：CDS 注解，为字段提供 UI 友好的显示名，会在 OData $metadata 与 Fiori UI 中体现。
  • Association to Authors / to Genres：声明「对一」关联，OData 中表现为可展开的导航属性（$expand=author）。
  • Association to many Books on books.author = $self：在 Authors 上声明反向的「对多」关联，用 on 条件指明关联键。$self 指当前作者行的 ID。
  • using { cuid } from '@sap/cds/common'：导入 CAP 公共类型库。cuid 是一个含 UUID 主键的抽象类型，第 5 章定义 Orders 时使用；本章的 Genres/Authors/Books 用 Integer 主键演示。

4.2 定义服务 srv/cat-service.cds

数据模型是「底层资产」，服务是「对外窗口」。在 srv/cat-service.cds 中定义 CatalogService，把模型投影成只读 OData 服务：

// srv/cat-service.cds —— 服务定义（服务层）
using { sap.capire.bookshop as my } from '../db/schema';

service CatalogService {
  @readonly entity Books   as projection on my.Books;
  @readonly entity Authors as projection on my.Authors;
  @readonly entity Genres  as projection on my.Genres;
  // @readonly entity Orders as projection on my.Orders;   // 第 5 章定义 Orders 后再启用
}

要点：

  • service CatalogService { ... }：声明一个服务块。CAP 会自动为它生成 /odata/v4/catalog 路径的 OData V4 端点。
  • entity Books as projection on my.Books：把底层实体投影为服务实体。my 是 sap.capire.bookshop 的别名。投影可以裁剪字段、改名、加注解，而原始模型保持不变。
  • @readonly：只读投影，客户端不能对 Books 执行写操作。本章先用只读；第 5 章会放开写能力并加自定义 Action。
  • 多个服务共享模型：同一个 my.Books 可以被多个 service 各自投影，每个服务只暴露自己需要的视图——这是 CAP 里「一个模型、多个服务」的最佳实践。
  • Orders 投影先注释：Orders 实体在第 5 章加入 schema，届时启用该行并补充完整服务定义。

4.3 种子数据 CSV

CSV 细节（完整数据在第 7 章）：

  • 表头顺序：必须与实体字段顺序一致，尤其是关联字段写成 author_ID、genre_ID（实体名首字母小写 + _ID），CAP 据此填入外键。
  • stock 覆盖三档：有 0（Eleonora）、小（5/10/12）、大（100/150/333），方便第 6 章验证 $filter 与第 5 章的下单库存校验。
  • price 覆盖两档：既有 < 30 的廉价书，也有 ≥ 30 的书，便于验证 price lt 30。

4.5 操作手顺

  1. 定义领域模型

    把 4.1 的代码写入 db/schema.cds，保存后观察 VS Code 左下角无红色报错。

  2. 定义服务

    新建 srv/cat-service.cds，写入 4.2 的服务定义。

  3. 放置种子数据

    在 db/data/ 下创建三个 CSV 文件（文件名、表头严格按 4.3）。

  4. 编译验证

    执行 cds compile db/schema.cds，确认输出无错误（见图 4-2）。

  5. 启动并查看服务文档

    执行 cds watch，浏览器访问 http://localhost:4004/odata/v4/catalog，确认返回三个实体集合（见图 4-3）。

💡 CSV 与本地数据库注意事项
  • 字段顺序：CSV 表头必须与实体字段声明顺序一致，否则启动时导入失败并报 invalid column。
  • 关联列名：author_ID / genre_ID 由框架约定生成，写错则外键无法解析。
  • 自动建表：本地 SQLite 数据库由 CAP 在首次启动时自动建表、自动导入 CSV，无需任何 DDL 手工操作。
  • CSV 编码：保存为 UTF-8（无 BOM），中文描述才能正确导入。
